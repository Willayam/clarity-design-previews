Speed pill 7A, plus two bar fixes it exposed

Real app, not a mock. Each image is a screenshot from a logged-in browser: before is production (2920e4be), after is this PR running locally. Light and dark are the app's own theme, driven by the OS colour-scheme setting. Contrast is measured from the rendered pixels of the pressed control.

1. The real player transport, speed pill pressed

Where the pill actually lives. 7A keeps the look you approved: same tint, same ink, contrast unchanged.

2. A pressed toggle inside dark media chrome

The case your screenshot caught. The bar set the pressed background but not the text colour, so on a light OS the text took the page ink, which is dark, on a dark bar. Now the bar owns the ink. Dark mode was never affected.

3. Keyboard focus on a bar button

The bar removes box-shadow, which is where Button draws its focus ring, and nothing replaced it. Before, focusing play, mute, fullscreen, or a toolbar toggle with the keyboard painted nothing. Now a 2px ring in the ring colour.

Source: branch ui/button-variants at e9b3fb8a, PR https://github.com/Clarity-Video-HQ/clarity/pull/679. Sections 2 and 3 inject a bar with the real Button class strings into the logged-in page so the app's real stylesheet applies.
