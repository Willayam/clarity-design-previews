Button batch 2: real-app before and after

These are screenshots from a logged-in browser. Before is production. After is PR 679 running locally. Light and dark are the app's own theme, following the OS colour scheme. Contrast and edges are measured from the rendered page.

1. Keyboard focus on outline and default Buttons, app-wide

The independent review found this. The surface rules for these two button styles set a box shadow for depth, and that shadow is where Button draws its focus ring. So no outline or default Button in the app has shown keyboard focus, on production today included. After this PR they show a 2px ring, the same one the toolbar uses.

2. The statistics modal action, keyboard focused

Verification found this one. The action sat against the edge of a scrolling container, which cut off the right side of the new ring. The action now sits 4px in from that edge, so the whole ring shows. The slot width and the text beside the button did not change.

3. The speed pill in the real player, pressed (7A)

This is where the pill actually lives. It uses the same tint and text colour as the old pill, and the contrast is unchanged.

4. The speed pill in the 270px card player

Button's default padding made the pressed pill wider than the old one, which pushed mute and fullscreen further past the edge of a bar that already overflows on production. With narrower padding the pill is no wider than production's.

5. Keyboard focus on toolbar buttons

The toolbar also removes the box shadow, so play, mute, fullscreen, and toolbar toggles showed nothing on keyboard focus. After this PR they show a 2px ring.

6. Video preview tabs, inactive tab hovered

The review found this. Without a fix, hovering the inactive tab turns its text near-black on the dark picker in light mode. After this PR the text stays light on hover and the tab uses the picker's own tint. The hovered tab is the one on the right.

7. A long folder name in the breadcrumbs at 360px wide

The review found this. Button text does not wrap by default, so a long breadcrumb would have overflowed a phone screen. After this PR it wraps, as it did before.

8. A pressed toggle on dark media chrome

This change prevents a problem rather than fixing a visible one. No real toolbar sits on dark media chrome today. The first 7A comparison page used that setting, which is why its pressed text was unreadable. The toolbar now sets its own pressed text colour, so the problem cannot come back if a toolbar is ever placed there.

9. Media picker alignment toggles: removed

Verification found that no caller ever passes alignment options to the media picker, so the toggles this PR had converted could never appear. They are deleted instead. The brand logo's alignment toggles are a separate component, already on Button, and are unchanged.

PR: https://github.com/Clarity-Video-HQ/clarity/pull/679. Sections 5, 6 and 8 insert controls into the logged-in page using the real Button class strings, so the app's own stylesheet styles them.
