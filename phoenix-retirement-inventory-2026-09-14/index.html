What “clean” means now

The core account runtime is native. Historical tables and stable wire names do not make it depend on Phoenix. Dropping them is lower priority than removing live legacy consumers and preventing new ones. Keep the stored owner IDs stable because media keys and workspace identities depend on their values.

Convex is still the live AI generation backend. Treat any move away from it as a separate architecture decision, not deletion of dead code. The immediate cleanup is the stale PRs, external integrations, remaining contact/training storage and Mux track.

The billing behavior that needs a decision

Phoenix’s charge.refunded and charge.refund.updated handlers can call Stripe to set cancel_at_period_end=true. Both event types are in the live legacy destination’s subscription list. The current Clarity webhook has no equivalent refund branch.

Decide whether automatic cancellation after refunds is still intended. If it is, its owner must move and verify that behavior before disabling the legacy destination. If it is obsolete, retire it explicitly. Do not reproduce the old behavior merely because it exists.

The Phoenix source revision is known; the deployed Fly revision is not. This establishes a concrete behavior to verify, not proof that today’s refund deliveries successfully execute it. The observed charge-success failures do not establish their cause.

Also, Phoenix’s customer.subscription.updated branch simply returns 200. A successful delivery is therefore not proof that it maintains subscription state.
