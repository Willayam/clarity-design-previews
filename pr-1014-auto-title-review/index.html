PR #1014 auto-title: is this the cleanest start?

Adversarial design review, 5 October 2026. Branch t3code/video-auto-title, reviewed at bae89bb0c, one fix pushed as e4dc1c302. PR #1014.

Verdict. No. The feature works and its tests pass, but it is not the cleanest start. All three reviewers, working independently, proposed the same smaller shape. It reuses the existing jobs table, keeps the transcript at Mux, and makes the share page follow the video field by field. I recommend that shape. Nothing below is built. You choose.

The strongest single reason is a product path, not code style. At finish the recorder hands the rep straight into the page editor (RecordVideoRoute.tsx, "Naming, copy, and CTAs live on the take's page"). The title lands at least a minute later, because the job is due 60 seconds after finish and then waits for Mux's captions. Any save in that window stores the page at revision 2 with an empty hero title and the name "Untitled Video", and the live-copy rule stops applying for good. That is the main flow, not an edge case.

The shape I would ship

  1. A video_title kind in jobs. jobInsert enqueues it in the finish batch for recordings and uploads, and a runner shaped like mux-discard-jobs.ts runs it. A discarded take's job gives up when it runs, as mux_clip does. A Mux video.asset.track.ready webhook can wake it sooner later on, but the cron stays the recovery path.
  2. No transcript in D1. The runner fetches the VTT from Mux on each attempt. The payload holds the default title and the result holds the outcome. Add a store when trim or search has a reader for it.
  3. Explicit eligibility. Auto may write only while the name is the server's own default (UNTITLED_VIDEO, or a filename stem that looks machine-made). It must not be "whatever finish wrote". The guarded write moves into video-row.ts beside nodeIntent.
  4. The page follows the video field by field. On a page made from a video, an empty hero title means "use the video's title" at render. The editor shows the live title as a placeholder and stores an empty string unless the rep types one. The data already has this marker: a take's page is born with hero title ''. This replaces the revision-1 rule, so saving a button colour no longer freezes the title.
  5. Delete the preview suggestion override. Keep the bare preview tick, because previews have no cron.

What it deletes from #1014. The video_autofill table and VideoAutofillRow. The custom claim, lease, backoff and 24-hour horizon. The transcript and caption-track columns and their codec. The three DELETE FROM video_autofill statements, including the special case bolted onto rowStatements. The unedited parameter and the revision predicate in the live-copy SQL. The override plumbing in preview-ticks.ts. Most of video-autofill-policy.ts. It still needs one migration, the rebuild of the jobs kind CHECK, as 0034 did.

Findings, ranked

Act on1. The first save freezes the page before the title arrives.

The editor GET bakes the live title into the document (journey-pages-native.ts). A save at base revision 1 stores it, and journey-page-title.test.ts asserts exactly that. The recorder opens the editor at finish, and the sweep writes the title at least a minute later. Any save in between stores '' and "Untitled Video" at revision 2, where the live read no longer applies. I confirmed the hand-off in RecordVideoRoute.tsx lines 524 to 535.

Fable and Codex. Lead confirmed.

Act on2. A second job system beside jobs, with weaker fencing.

video-autofill.ts rebuilds the claim, lease, backoff, failure counter and terminal states that jobs-store.ts already provides, and it has no retention. Only the claim is fenced. Later writes key on node_id alone. Codex reproduced the consequence in SQLite. A runner whose 5-minute lease expired resumed after a newer runner took over. The result was two model calls, the newer runner's title, the older runner's saved suggestion, and an outcome of user_owned although autofill wrote the title. The lease is also computed from the sweep's start time, so slow early rows eat the lease of later ones.

All three seats. Codex reproduced the overwrite.

Act on3. The stored transcript has no reader and no retention.

Only runOne reads video_autofill.transcript. Nothing reads caption_track_id. The transcript is fetched and stored before the check for a user-owned name, so takes the rep already renamed still copy their full speech into the auth database. Done rows keep it until the take is deleted. Main deleted video_transcripts in WIL-3418, and this brings a transcript store back for trim and search code that does not exist yet.

All three seats.

Act on4. "Still has the name it finished with" is not "the user never chose a title".

enqueueAutofill runs INSERT ... SELECT name after the nodeIntent statement in the same batch, so default_title is whatever title finish wrote. Recordings send "Untitled Video". Uploads send the file's display name. A human-named file such as "Pricing walkthrough for Acme" survives only if the model obeys "return it unchanged", and any paraphrase overwrites it. Codex ran both failure cases on the real code. A title supplied at finish was replaced, and a rename away from the default and back again was replaced. The rule is race-free for concurrent renames to a different value. All three seats traced that SQL and agree.

All three seats. Codex executed it.

Act on5. "Unedited page" now has three predicates.

Retirement uses revision 1 plus updated_at <= created_at (UNEDITED_PAGE_SQL). The editor's live read uses draft revision 1. The public live read uses publication revision 1. A comment in video-share-page.ts admits the difference, and a test locks it in. Opus traced the consequence. A rep sets a password on a take's page and later deletes the video. Retirement treats the page as edited and keeps it published. The live read then finds no video, so the title falls back to the stored empty value. This is the "one rule, several statements" bug class the August panel named. The field-level page reference in the recommended shape removes the need for the live-read predicate.

All three seats.

Consider6. Private Library renames now reach prospects.

Before #1014, a rename after finish never touched the page. Now any Library rename changes the public title, og:title and heading of every unedited share page. A label such as "Acme, lost deal" becomes what the prospect sees. The test "reads a Library rename without a page write" asserts this. It is a product decision wider than auto-title, so make it on purpose.

Opus.

Consider7. An unreviewed model title goes public, and non-English speech yields confident nonsense.

Main asks Mux for English captions on every asset (packages/mux/src/client.ts, generated_subtitles with en). Mux transcribes in the language it is given and does not detect. A Swedish take gives English-shaped nonsense with state ready, and only a prompt line guards it. The title lands on a page that may already be shared, with no review step. Sales calls name people and competitors, and the prompt admits names may be misspelled. Options are a code-side language or confidence gate before the call, or writing the title to the video only until the rep has seen it. Prompt injection is bounded to one string of at most 80 characters, so it is a copy-integrity risk, not a code-execution one.

All three seats.

Consider8. The data boundary is a policy call for you.

This is Clarity's first flow that sends a customer's speech to OpenAI without a user action. That includes prospects' voices when they are on the recording. The mechanics are sound. The transcript is marked untrusted, the schema is a single string, gateway payload logging is off, and provider bodies never leave the module. The question is the subprocessor and retention position, not the code.

All three seats.

Consider9. A missing key is recorded as a finished decision.

Without a model, the row stores {"unavailable":"no_model"} and becomes done. Adding the key later does not resume it. A revoked key (provider_401), truncation and refusal all collapse into the same no_model label and a console.log, so a 100% failure rate would be invisible. In the jobs shape a missing key should leave the job pending, and permanent provider failures other than refusal should reach Sentry.

Codex and Opus.

Consider10. The preview suggestion override is dead once previews have a key.

deps.suggestTitle wins over options.suggestion, and the test "uses the preview override only when no model is configured" shows an injected title being ignored. Delete parseSuggestion, TickInputError, the body parsing and AutofillOptions.suggestion. Keep the bare tick and its ?node= filter.

All three seats.

Consider11. withLiveVideoCopy restates the page builder.

The hero title, the hero-detail insert and remove, and the page-name fallback are written twice, and the two copies already differ. The builder falls back to video.name then video.filename. The live path gets '' when metadata.title is an empty string, because COALESCE does not skip empty strings.

Opus.

Dismissed

  • Fable's "critical" labels on findings 2 and 3. The code works and its tests pass. These are design debt worth acting on before merge, not breakage.
  • Reviving the August spec-table-plus-reconciler design for this. All three seats agree it does not apply as a mechanism, since main deleted the derivation pipeline and Mux now holds the declared asset. Its surviving principle, one statement per rule, is what findings 3, 5 and 11 apply.

Your six questions, short answers

  1. Cleanest start? No. See the recommended shape above.
  2. Does the transcript store earn its place? No. It is speculative for trim and search. Finding 3.
  3. Is the default-name rule right and race-free? It is race-free against concurrent renames. It is the wrong rule for titles set at finish and for human-named upload files. Finding 4.
  4. Data boundary and the preview route? The data boundary is a policy call (finding 8). The override should go once the key ships (finding 10).
  5. Failure modes? No speech used to call the model anyway, which is now fixed. No captions are abandoned 30 minutes after ready. Non-English speech and unreviewed titles are findings 7 and 9. Cost is one small call per take with model retries capped at 3.
  6. House fit? The guards in docs/agents/guards.md hold. The one-rule-one-statement principle breaks three times (findings 3, 5, 11). CONTEXT.md gains a "Transcript" entry that describes a storage location. An "Automatic title" entry would describe the domain.

What I fixed

e4dc1c302, pushed to #1014. Both changes are in video-title-suggester.ts, which survives any of the redesigns.

  • The request bound was not a bound. The 12,000-character check elided only transcripts with more than 50 cues, so 50 long cues went whole. Codex measured 50,993 characters. Each cue is now capped at 200 characters, so the 50-cue window bounds the request.
  • A silent take called the model. Empty cues now return no title without a call.

Two new tests fail against the old code and pass against the fix. The router suite (182 tests), the workspace-tree suite (522), the touched editor tests (75), ESLint and the test-type budget (207 of 250) all pass. A real model call is unverified, because previews have no key yet.
