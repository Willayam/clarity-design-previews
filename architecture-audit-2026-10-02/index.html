The foundation is closer than the directory tree suggests

Keep the current deployment shape

Two deployed Workers handle the app and media. Library and email code run in the app process. Accounts, pages, and Library share one physical D1 database. The old worker folder names do not describe deployed services.

Keep the recent correctness work

Server-owned generation jobs, immutable published revisions, a Stripe retry inbox, generated D1 row types, one entitlement decision, and one playback policy already remove substantial risk.

Verified against current architecture, the event inbox, and publication caching. Convex generation, legacy R2 video playback, and the old cross-database page projection are already gone. Do not start those migrations again.

Which errors can construction prevent?

Types prevent some invalid local programs. Validation and database constraints protect stored facts. Durable retry protocols manage external failures. These mechanisms have different guarantees.

Correctness follow-ups and migration gates

Discard jobs need a rearm rule before the production handoff

A subject-only dedupe key survives a completed “held by live take” job. A later release of the last holder may then fail to enqueue new deletion. Direct deletes can mask this today. Test two holders released at different times before making the durable runner the only owner.

Latent source-derived migration risk. Enqueue key · Held result · Completion

Parked trims need an owner-visible terminal state

Eight failed attempts can park legacy clip work with no next due time. Playback readiness still describes the playable source, so the owner can see no explicit failed-trim status. Count parked rows before assigning incident severity. Preserve the prior published clip.

Source-derived risk; no production instance observed. Parking behavior · WIL-3453

Construct email logs from a safe allowlist

The log payload stores the request object, which can include a password-reset URL. Define the log record separately from the send request so usable credentials cannot enter it through ordinary logging.

Existing security follow-up WIL-3490. Payload construction. No customer data or log contents were inspected.

Make session revocation an explicit account decision

Eight-hour stateless sessions do not provide individual-session revocation. Evaluate a version or revocation check through the existing identity read, or verified provider-managed sessions. Account suspension is already checked and should remain centralized.

A deletion-led implementation order

  1. Close small correctness gaps first.

    Validate block identities, preserve a new draft on leave, batch page events, stop logging reset credentials, and carry retry identities. Each is small enough for a focused reproduction and review.

  2. Finish the video ownership migration.

    Complete cohort parity, clip jobs, discard rearming, and owner-visible edit status. Retire the metadata bridge and old scheduler only when their replacements own every caller and recovery path.

  3. Narrow page and Library contracts.

    Introduce discriminated references and parsed responses incrementally. Replace kind-erasing edits. Remove aliases only after persisted compatibility and callers have moved.

  4. Converge the Library and delete duplicate presentation.

    Share the folder path, cards, capabilities, and bounded rendering. This is the largest clear UI deletion. Delete the hero CTA adapter as a separate small change.

  5. Optimize the measured customer path.

    Record route, query, interaction, upload, generation, and playback timings. Change the largest verified contributor first. Explore a shared block renderer or Workflows only if the experiment proves net deletion without a product regression.

Retirement requires a data census

Potential later deletions include legacy expiration writes, dormant page share and preview columns, old media aliases, and the retired email provider. Check exports, support queries, persisted rows, and rollback requirements. WIL-3495 places retired database deletion on or after 8 October. Do not erase that rollback window. Preserve the account policy decisions in WIL-3461.

The audit makes no reliable line-count or speedup promise. A change earns its complexity by deleting an old authority, reducing an observed bottleneck, or enforcing a named invariant.
