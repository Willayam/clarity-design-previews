Short answer

The app has one shared segmented component, SegmentedControl. It is the most used segmented style (12 placements from 7 call sites), and every one of those placements is in the journey page editor: the side panel and the Style pop-down. So it is the standard segmented control for property panels.

The real Edit Video modal uses a different control for the same job. Still Preview and Moving Preview are two ghost Buttons with aria-pressed on the dark media glass of the video dock. The floating text toolbar and the media toolbar on the page canvas use the same pressed ghost buttons. The prototype took the panel control into the video dock, which is likely what feels off.

The prototype also draws a blue Done inside the dock. The real Button cannot do that: inside a media surface every Button variant paints transparent (button.tsx:189-199). The real dock's Done and Cancel are both ghost, and the modal's blue Done sits in the footer, off the glass.

Recommendation: build all three toggles as pressed ghost groups, copying the markup of the real Preview type group, with a ChromeSeparator between groups. Make Cancel, Done, Undo and Restore ghost sm, as the real dock does. If Done closes the whole modal, move Cancel and Done off the glass and use the app's dialog pair, an outline Cancel and a default Done.

Inconsistencies

In the real app:

  1. Three looks pick one value out of a few: the SegmentedControl well in panels, pressed ghost buttons on chrome and the video dock, and the ChromeSegmented sliding thumb. The thumb has one use, and it sits in the same media toolbar as pressed ghost alignment buttons.
  2. Text alignment is the same field in two places with two looks. The side panel uses SegmentedControl beside the title input. The canvas toolbar uses pressed ghost icons. surface.tsx says the container decides a control's look, which explains the split, but SegmentedControl does not read the surface at all.
  3. The chosen state changes color by place. Pressed ghost is blue-tinted on a page or panel (--btn-tint) and grey on chrome (--cg-active). SegmentedControl raises a neutral segment. Recorder tiles go blue.
  4. The three choice tile groups draw the chosen tile three different ways (ring outline, ring border plus inset ring, blue border plus fill).
  5. ui/tabs.tsx has no call sites. Its line look was rebuilt by hand in SectionNav, so the underline tab now exists in two implementations, one of them unused.
  6. Cancel and Done differ between the dock and the dialogs. Dialogs put an outline Cancel left of a default primary. The video dock stacks Done above Cancel, both ghost sm. The media picker uses lg, the other dialogs the default size. DeleteConfirmationDialog overrides its outline Cancel with hand-written classes and paints its delete button bg-red-500 by hand (DeleteConfirmationDialog.tsx:112-129).
  7. Two switch implementations: ui/switch.tsx and the hand-rolled CtaPrimarySwitch.

Between the prototype and the real modal:

  1. The prototype restyled its toggles to look like SegmentedControl, while the real modal uses pressed ghost buttons for Moving and Still.
  2. The prototype's segmented buttons are aria-pressed buttons dressed as SegmentedControl. The real SegmentedControl is a radio group.
  3. The prototype's Done is blue inside the console. Inside the real dock, every Button variant is transparent.
  4. The prototype's Undo is a blue link. The real Undo on #1016 is a ghost sm button in white.
  5. The prototype's console turns light in light mode. The real dock stays dark media glass in both schemes.
  6. Labels and order: the real modal says Trim and Edit Preview, and Still Preview before Moving Preview. The prototype says Trim, Preview, Moving, Still.

Buttons

editor/src/components/ui/button.tsx names the roles in its header comment: default is primary, outline is secondary, ghost is tertiary, destructive is danger, link is inline, dashed is the add row in a panel, and plain is an icon inside a field. Gold and ink are marketing faces. secondary is defined but unused, because on the near-white card it looks the same as outline. The surface decides the face: on a hero surface default is a gradient and outline is frosted glass, a panel keeps them flat, and on a bar or media surface every variant turns transparent.

What DESIGN.md says

Nothing about segmented controls, tabs, toggles or button hierarchy. It covers glass (chrome over content only), type, color, spacing, layout, radius and motion. The rules for these controls live in code comments:

  • ui/segmented-control.tsx: one value out of a few, a radio group that wears the Tabs list's track, and not Tabs, "which would announce panels that do not exist".
  • ui/surface.tsx: "Appearance is decided by the container, never by the call site." A panel is flat. A bar or media surface makes controls transparent with a tint on hover and when pressed.
  • ui/button.tsx: the variant roles listed above, and secondary unused.
  • SectionNav.tsx: "Links, not ARIA tabs: each entry is its own URL."

docs/agents/guards.md has one related lint: a raw <button> fails CI, and the message says to use Button or ButtonBase and to treat a missing variant as a change to the primitive. No lint or guard says which segmented control to use.

Method

  • Inventory: git grep over editor/src on origin/main 41bfc02ed for SegmentedControl, Tabs, RadioGroup, ToggleGroup (none exist), aria-pressed, aria-checked, data-active, role="group", ChromeSegmented and SectionNav, then read each hit.
  • Live crops: the PR #1016 preview (feat/auto-trim, which adds the auto-trim Undo line to the dock), the QA account, Chromium at 2x, OS color scheme dark and then light.
  • Rows A to C were rendered in the live modal by cloning real rendered app elements into the dock. Nothing was clicked that saves: Trim and Edit Preview were opened and left with Cancel, and the modal was never closed, so its close-time save never ran.
  • Not captured live: Tabs (no call sites), the classic radio list (inside the cancel-subscription dialog), ui/switch.tsx, the gallery column stepper (no gallery block on the QA page). Video frames and filmstrips are kept out of the crops.
