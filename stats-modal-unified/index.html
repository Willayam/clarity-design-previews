One stage. Data thins, layout stays.

Every state below is the same skeleton: header with the numbers, thumbnail beside the retention curve and seek bar, ruler, column head, rows. There is no note card, no metric tiles, no second chart. When a piece of data is missing its slot either collapses or carries a one-line message in the same typography as the rows.

Numbers live in one place: the header line.Sessions, imported totals and stored summaries all format to the same sentence shape: views · past halfway · average watched. Segments drop when the data is missing. The four imported tiles are gone; their numbers were always derivable from the same sentence.
The retention curve is the hero in every state.Imported history has retention too, so it gets the same curve, seek bar, ruler and scrubbing readout. When no sessions exist the readout says "1:23 · 66% still watching" instead of "4 of 17 watching".
The rows grid is the only list.Sessions fill it when they exist. Imported history fills it with locations instead: Where · views · share-of-views bar. Empty, failed and loading all render inside the rows slot, so nothing ever jumps.
No provenance at all.Nothing in the modal says "imported". Where the numbers came from is a data-layer concern; the viewer only needs the numbers.

What this deletes from the component

  1. The whole imported branch. ImportedStatsSummary and its note card, metric tiles, halfway line, second retention chart and locations list, plus every .video-stats-imported-* rule (about a quarter of the stylesheet).
  2. The six-way branch in VideoStatsModal. Today the modal picks between failed, loading, imported, unavailable, empty and stage. After: the stage always renders and only the rows slot varies. source_provider stops being a UI concern.
  3. Four one-off layouts. .video-stats-state, .video-stats-state-error, .video-stats-empty-callout and .video-stats-import-error collapse into one .video-stats-slot.
  4. Two summary-line formats. One summaryLine(stats) for every case; segments drop when the data is null.
  5. The narrow media query for imported tiles. Gone with the tiles. The remaining narrow rules cover one layout instead of two.
  6. Nothing new for "no retention". buildCurvePath([]) already returns a flat baseline; the dashed stroke is one attribute.

Net: one layout, one rows renderer with two row shapes (session, location), one slot message. Roughly a third less TSX and CSS than today.

Decisions this needs from you

  1. Header sentence for aggregates. Proposed: 2 views · 2 past halfway · 100% watched on average. Unique viewers and total watch time are dropped from the line. Keep either?
  2. Location rows. Accepted as a fallback. Open question is only whether the lane shows a share-of-views bar (as mocked) or stays empty with just the count on the right.
  3. Narrow thumbnail. Proposed: shrink it into the header beside the title instead of hiding it. Cheap to drop if it feels busy.
  4. Empty state. Proposed: the same stage with a flat curve and the share CTA in the rows slot, so a brand-new video already looks like the thing it will become.
Proposal, not shipped code. Mock data. Thumbnails are placeholders.
