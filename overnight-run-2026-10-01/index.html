Things you should know

Concurrent saves now merge instead of overwriting the whole page. Page saves carry the revision they started from, and the server refuses a stale one. The writer then merges its changes into the latest draft, field by field. Two limits remain. When two tabs change the same field, or the same list, the later save wins and the earlier text in that field is replaced. And an edit beats a delete: if one tab deletes a block while another edits it, the block comes back with the edit.

One rare case is accepted, not fixed. Please judge it yourself. If a save reaches the server but its answer is lost on the network, a block the rep deleted moments before can come back. At the next generation the editor then says "We couldn't confirm your last save. If you deleted something just now, check it's still gone." At the next ordinary save conflict it happens with no notice. Closing it needs server-side write history, which I judged not worth building overnight. I told the final #874 reviewer not to re-raise this case, so its approval doesn't cover it.

Library errors in Sentry are now tagged worker=clarity-frontend instead of clarity-workspace-tree once the fold lands. Alerts filtered on the old tag will stop matching.
