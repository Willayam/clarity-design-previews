Clarity / browser recorder / research spike / 1 November 2026

Clean up the live mask first. A second pass has a much higher price.

Measured on this Apple M4 in Chromium. The cheap curve removes 40 to 49% of the soft alpha band in these six frames. Edge-aware refinement removes 46 to 59%. These are reductions in translucent pixels, not accuracy gains.

Recommendation · inferred

Start with the alpha curve. Add the joint bilateral shader where the recorder has enough frame budget. A new matting model should be an explicit quality option, with a preview and an estimated wait. It should not delay every recording automatically.

The stronger models improve some hair and shoulder edges, but static image quality is not enough. Both MODNet and BiRefNet lose parts of the moving hand. ViTMatte keeps more of it, but its trimap still inherits MediaPipe mistakes. No method can recover a detail confidently marked as background without widening that uncertainty.

3× hair motion crops

Temporal blending reduced mean frame-to-frame alpha change in the uncertain band by 10.3% in the clean clip and 13.4% in the harsh clip. This proxy includes real motion and is not a ground-truth flicker score. The blend uses 65% current alpha and 35% previous alpha only when their difference is below 0.2. Large changes reset to the current mask. It has no optical flow.

Inferred from measured frame costs Half-resolution ViTMatte at 185 ms per frame implies about 5.6 minutes for a 60-second take before other export work. Full-resolution ViTMatte is 851 ms per frame, about 25.5 minutes. Its edge improvement is modest on this footage. BiRefNet WebGPU implies about 38 minutes. These costs do not justify a mandatory pass after every recording.

WebGPU correctness is a release gate

For every ONNX candidate, the same float32 model and the same input are run through WASM and WebGPU. All six frames are compared before accepting the GPU result. BiRefNet and ViTMatte pass at an alpha difference threshold of 0.01. MODNet fails badly at both tested resolutions. Its faster GPU times must not be used to justify a product decision.

At 512 × 288, MODNet differs from WASM by more than 0.01 in 32.3 to 38.2% of pixels. Thresholding at 0.5 changes the person/background classification of 17.0 to 24.2% of pixels. The failed output is included in the gallery. BiRefNet's largest difference in the six frames is about 0.000032. Exact per-frame results are linked below.

What belongs in Clarity

Inferred The curve belongs in person-matte first. It can be folded into the existing alpha-writing loop without another model, download or full-frame shader pass. Its purpose is to remove low-confidence fringe, not reconstruct missing hair. Keep the untouched raw plate.

Inferred Joint bilateral upsampling is a viable live option on this M4. The shader samples the original full-resolution RGB image to place the boundary, then applies the curve. It adds GPU upload, sampling and synchronization work. Use a frame-time budget and retain the curve-only fallback on weaker devices. The tested implementation is a 5 × 5 kernel with spatial sigma 1.5 mask pixels and RGB sigma 0.12.

Inferred Temporal blending is a smaller improvement. The included clip lets the product owner judge the reduction against lag around the hand. It should reset at discontinuities and seeks. Optical-flow alignment and a real webcam capture were not tested.

Inferred A heavy second pass earns its place only when the person is prominent, the preview shows a worthwhile improvement, and the user accepts a multi-minute wait. ViTMatte is the most useful candidate here because the live mask supplies a trimap and it keeps more of the moving hand. BiRefNet lite costs too much and still drops fingers. MODNet's good WASM hair edge does not compensate for its missing hand on this take.

Verified from source / integration inference The plate already preserves the raw camera. Restyle extracts the camera crop in restyle-painter, segments it, then sends the matte to paintScene. A quality choice can select the matte implementation in that path with no plate or project schema change. ONNX inference is asynchronous, so the painter and render loop must await it. Load the chosen model once, reuse buffers, report progress, and release it on cancellation. Run the pass from the plate, never from an already cut-out export. This remains browser work; Workers and R2 only deliver the existing data and model assets.

Licence and model provenance

Checked against primary sources on 1 November 2026. The three heavier model families are the only ones tested. No downloaded model repository code or pickle checkpoint was executed. The spike loads ONNX data through ONNX Runtime Web.

  • MediaPipe: Apache 2.0 code; the official selfie model card explicitly gives Apache 2.0 for the weights. Model input is 256 × 256. The Tasks API returned a 512 × 288 mask after the recorder-style input resize.
  • MODNet: the official licence statement explicitly covers code, models and demos under Apache 2.0. Tested the photographic ONNX weights linked by the author's ONNX README. Both 512 × 288 and the author-style 896 × 512 input were tested. The webcam-specific checkpoint was not tested.
  • BiRefNet: MIT source code and MIT official lite weights. The tested 199.68 MB ONNX export declares MIT, identifies the official weight revision, and replaces deformable convolution with a GridSample decomposition. It avoids a documented memory failure in an older dynamic export. The official model zoo also has portrait and newer matting variants, but their larger backbones were not tested.
  • ViTMatte: MIT original code; the official hosted small Distinctions-646 weights are labelled Apache 2.0. The ONNX conversion links that source checkpoint. RGB normalization follows its processor config. A 9 × 9 min/max operation builds the trimap from the live mask at 640 × 360. Values below 0.05 are known background and above 0.95 known foreground only when their whole neighbourhood agrees. Other pixels are unknown. The input is padded to 640 × 384 after normalization, then cropped back. A second resolution test uses the original 1280 × 720 camera pixels, pads to 1280 × 736, and keeps the 9 × 9 trimap neighbourhood. That narrower relative band is a limitation of the comparison.
  • ONNX Runtime code is MIT. This run uses ORT Web 1.31.1, float32 weights, and MediaPipe Tasks Vision 1.2.0. ORT reports some operators assigned to CPU, so WebGPU here means the preferred execution provider, not a guarantee that every node ran on the GPU. The MediaPipe JS + WASM runtime adds about 15 MB uncompressed. The ORT WebGPU runtime adds about 29.6 MB; its WASM-only runtime is a separate roughly 28 MB download. ViTMatte also needs MediaPipe to create its trimap. Network transfer size with compression and cold download time were not measured.
  • RVM, RMBG, MatAnyone and CorridorKey were excluded as requested. RVM is GPL-3.0. RMBG 1.4 and RMBG 2.0 use BRIA terms requiring a commercial agreement for commercial use. MatAnyone has non-commercial terms. CorridorKey was not downloaded or tested.

Measurement limits and reproducibility

Apple M4, 10 logical CPUs, 16 GB memory. Chrome 156.0.8078.76 with ANGLE Metal renderer, not SwiftShader. The WebGPU adapter reports Apple, metal-3, and isFallbackAdapter=false. The initial shared-browser probe used SwiftShader and was discarded. WASM uses four requested threads with cross-origin isolation enabled. Another two CPU cores were busy with existing applications during the run. Those processes were left running.

Each live candidate receives the same six frames in five batches with rotated candidate order. ONNX backends each run five six-frame batches after warm-up, except full-resolution ViTMatte WASM, which has one reference batch; WASM and WebGPU batches are grouped, not alternated, so their direct speed ratio is not a controlled crossover experiment. The full render does alternate candidate order. The numbers are single-machine measurements, not a fleet prediction.

Micro timings use performance.now(). MediaPipe reads the confidence array before the timer stops. The shader calls gl.finish(); Canvas2D reads a pixel after compositing. ONNX awaits session.run() and output data before timing completes. The benchmark records finite values, output minima/maxima and mean alpha, saves images and raw ONNX alpha arrays, and compares GPU output to WASM. The heavy paths spend most time inside inference. The live shader path adds full-frame upload, sampling and synchronization. Phase timings identify those dominant stages; this run does not distinguish GPU arithmetic from memory bandwidth inside an operator.

PNG loading, asset writing and correctness comparisons are outside the micro timers. The microbenchmark uses a readback-oriented Canvas2D context. The full render uses normal Canvas2D contexts and goes directly to the encoder, so multiplying the microbenchmark cost is not a substitute for the complete render measurement. Frames were decoded explicitly with FFmpeg after a preliminary HTML-video seek test returned repeated images. Those preliminary results were overwritten and discarded. All final clean source frames have different pixel content. The clean footage is first scaled to 1280 × 720, encoded at CRF 18, then decoded. The harsh variant applies 0.58 contrast about mid-gray, subtracts 25 code values, and adds seeded shared-channel uniform noise with amplitude ±15. This approximates poor light; it is not a calibrated webcam noise model.

The Commons clip has no ground-truth alpha. The fractional-band count and temporal variation are descriptive proxies, not segmentation accuracy or a perceptual score. The subject, background and lighting are narrow. Long hair, different skin tones, eyeglasses against new backgrounds, low-end laptops, Safari, real camera noise, live recording contention, model quantization, FP16, foreground colour decontamination, optical flow, and neural-matting video stability were not tested. The neural models were assessed on three times in two conditions, not a full 60-second neural export.

No product file, git branch or remote service was changed. The page contains only Commons-derived images and a synthetic screen. Nothing was published.
