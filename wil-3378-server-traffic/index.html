Aggregate traffic, separate account conversion

16 September 2026 · WIL-3378

Traffic uses daily server counters without visitor fingerprinting. Signup → page creation → payment remains a separate server-event funnel.

Public page request → local daily counter
Scheduled export → PostHog aggregate report

Live staging proof

Two controlled page requests increased the local counter from 0 to 2. The scheduled job exported the counter, and PostHog stored a total of 2. The stored identity represents the aggregate bucket, not a visitor; person processing is disabled.

The payload contains only count, route, environment and deduplication metadata. No browser, device, session or referrer fields were stored. PostHog's IP field contains Cloudflare's shared Worker sentinel, not a visitor address.

What the counts mean

Successful server-served marketing/signup HTML requests, grouped by UTC day and route. Reloads and bots count. Client-side navigation, prefetch, DNT/GPC and failed database writes are excluded. These are not unique visitors or an attributed visitor-to-signup conversion rate.

Checks

  • Atomic increments and exports preserve counts during concurrent requests.
  • Retries keep stable snapshot UUIDs; reports take the maximum counter, so duplicates do not inflate totals.
  • No vendor requests are sent from a visitor's request context.
  • Detailed browser analytics remain opt-in; the unused cookieless client is removed.
  • Focused tests, report/health tests, typechecks, lint, build and CI pass.
