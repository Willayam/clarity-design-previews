Problem. Five call sites write the six X-Clarity-* headers by hand, and they already disagree: a System Admin arrives as admin through the proxy and as user through the other two paths. Today workspace-tree reads the role only for admin content counts, so the drift is latent, not a live bug. Each request also decrypts the session and reads D1 up to three times.

Solution. The auth-identity package owns encode/decode for the wire contract and the Convex claims. fetch resolves a memoized request context once and passes it to handlers.

  • Locality: the role rule lives in one file
  • Tests: one round-trip test covers the seam
  • Fewer D1 reads per request
  • Makes the WIL-3401 route table easier

Problem. Poster and GIF each copy the claim → admit → publish skeleton, and the copies have already drifted. Only 2 of 6 kinds retry when a driver throws. The Durable Object name that serializes drivers is built by hand in 7 places. ready_unpublished still has no terminal state. Two edit paths decide invalidation independently, and the poster-nulling list is written four times.

Solution. One drive() owns the lifecycle, and each kind is a small recipe. A single pure invalidation module maps an edit to the slots to clear and schedule. Poster moves to a digest key, the way GIF and clip already work.

  • A retry fix applies to all six kinds
  • Tests drive drive() on SQLite with a fake producer
  • index.ts goes back to being a thin adapter
  • Also closes the CAS loops that bypass node-metadata-cas

An account read model: one "current subscription" rule and one entitlement read

Stronglocal-substitutableM

frontend-router/src: account-profile.ts:168-262 · stripe-checkout.ts:206-345 · admin-accounts-native.ts:228-300 · trial-offer-with-stripe-sync.ts:20-70 · trial-wall.ts:72-83 · convex-auth.ts:66-73 — editor/src/lib/trial-access.ts:8

Problem. ADR-0008 centralised the entitlement rule, but reads are spread over six files, and "which subscription is current" is answered three ways. Callers disagree on what happens when the read fails: the trial wall allows, convex-auth refuses with a 503, and the offer route throws. Solution. An account read module next to account-spine. readEntitlement(…, { onUnavailable }) makes every caller state its failure policy.

  • ADR-0008's approach extended to reads
  • The plan rule is testable without SQL
  • Removes a large share of router SQL fakes

A Library item module (finishes the Library convergence)

Strongin-processL · ~900 lines move

editor/src/routes/HomeTreeRoute.tsx:154-330, 463-1274 · lib/tree-media-adapter.ts:33-83 · components/LibraryGrid.tsx:67 · components/AppSidebar.tsx:398-470

Problem. Home and the media picker classify a tree node differently. Home treats a legacy "video" that is really an image as an image, and the picker files it as a video, so the two surfaces disagree today. Rename and delete are written twice, in cards and in the sidebar. The journey-page delete rule (a 404 falls back to deleting the tree node) sits inline in a click handler. No test touches HomeTreeRoute.

Solution. One module turns a node into kind, name, preview, link and allowed actions, and owns rename, move and delete with optimistic restore. Home, the picker and the sidebar become views over it.

  • The classification disagreement is fixed once
  • Card behaviour is testable without the route

StrongS

justfile:82-87, 131-167 · scripts/cloudflare-ops.sh:61-132 · .github/workflows/cloudflare-deploy.yml:51, 676 · DEPLOY.md · workers/{r2-media,auth-email}/DEPLOY.md

Problem. deploy-staging/deploy-production push Convex, and DEPLOY.md never says so. The worker list is hard-coded in 5+ places, D1 bindings are listed twice, and the per-worker DEPLOY files are stale.

Solution. deploy/workers.json is read by the justfile, the ops script and the workflow, and a test checks that DEPLOY.md agrees with it.

Smaller wins seen along the way

  • Journey Page submissions table (Strong, S): Contacts has a hidden ?journeyPageId mode that copies LeadsRoute almost line for line, and the CSV download is written three times. Removes about 150 lines.
  • Contacts module (Strong, M): the CSV parser, import mapping, dedupe and CRUD sit inside a 1,556-line route and use raw apiFetch, which skips shared error handling.
  • WorkOS client (Worth exploring, M): the base-URL normalization is copied about 10 times, and auth-session.ts mixes 12 routes, raw WorkOS HTTP calls and telemetry. Tests stub global fetch 33 times.
  • Journey Page lifecycle (Worth exploring, M–L): create, update, duplicate and delete each coordinate three stores with a different failure policy, and there are two different access predicates.
  • Typed r2-media RPC (Worth exploring, S): workspace-tree hand-copies r2-media's method payloads, and nothing makes the compiler check them against each other.
  • Validated Env (Worth exploring, M): 93 runtime checks for missing bindings in the router, with 503-vs-null disagreements. This is WIL-3401 and needs sign-off.

Top recommendation

01 · Identity codec and request context, then 02 · one derivation driver

01 is small, two explorers found it independently, the drift already exists in the code, and it makes the pending route-table work (WIL-3401) simpler. 02 has the most leverage: most open video-job bugs trace back to six drivers that each hand-roll the same lifecycle. Doing 03 first makes both cheap to test. Because pure Mux was decided today, 04, 05 and 10 should be decided before more code lands in the upload and playback paths.
