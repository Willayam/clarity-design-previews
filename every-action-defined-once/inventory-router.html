Inventory

This inventory is for main at e839a6bd5. I counted a successful method and path pair once. HEAD variants, OPTIONS preflights, rejected methods, and query variants are shown but excluded from the counts below.

The route table is a policy declaration, not the auth implementation. It dispatches public rows, then the trial wall, then app rows. Handlers perform session and ownership checks after dispatch (workers/frontend-router/src/route-table.ts:143, workers/frontend-router/src/routes.ts:384). The global origin guard runs before dispatch (workers/frontend-router/src/security-headers.ts:57).

Table shorthand: A/P/V mean AUTH_DB/PAGE_LIBRARY_DB/VIDEO_STATS_DB; S means cookie session; SA means acting System Admin; O means a stored owner or workspace check; H means hand parsed; J means an ad hoc JSON response. Wall means the trial wall checks a mutation; exit means a lapsed account may perform it; read means GET/HEAD passes the wall unless suspended; bypass means the public row or telemetry exception avoids it. None in the event column means no named analytics event was found on that action path, not that the Worker has no logs.

Counts

For a reproducible count, I counted the router’s 70 successful /api method and path pairs in the first table, excluding HEAD as a representation of GET and excluding OPTIONS. That set has 22 primarily read and 48 primarily write actions. It includes the two webhook entry paths. It does not split /api/admin/commands into its eight command variants or split public page intents by form/query value.

The router exposes 26 additional /api/tree forwarding pairs, of which 12 are reads and 14 are writes by HTTP method. MCP adds 9 operations, 8 reads and 1 write. These sets total 105 entries, 42 reads and 63 writes, under that counting rule. A GET can still write as a secondary effect: checkout return, trial-offer Stripe reconciliation, CSV export audit, and legacy /watch migration are examples.

All 9 MCP operations have Zod mini input schemas. I found 0 Zod input schemas in the 70 router-owned API actions examined. Body-bearing router actions use hand parsing, package validators, or provider verification. Exact hand-parsed versus no-input counts are not reliable at method and path granularity: several rows accept optional bodies, and the two proxy boundaries hand validation to another service. The meaningful measured split is 9 Zod MCP definitions versus 0 Zod router HTTP definitions.

The trial wall is implicit for app HTTP paths, not attached to each capability. Of the 48 primarily writing router-owned /api pairs, 39 are ordinarily gated by the wall, 4 are explicit lapsed-account exits (checkout start, page delete, unpublish, agent revoke), and 5 bypass it as public/provider/telemetry writes. Among the 14 Library-forwarded writes, node DELETE is an exit and the other 13 are ordinarily gated. These counts follow the exact exceptions in workers/frontend-router/src/trial-wall.ts:191 and workers/frontend-router/src/trial-wall.ts:210.

Non-obvious things

  • GET /api/billing/stripe/checkout-sessions/return is a state-changing reconciliation path, including under HEAD (workers/frontend-router/src/stripe-billing.ts:161). The wall treats it as a read.
  • A first visit to an old /watch/:id can create a page, publish it, enable its route, and redirect (workers/frontend-router/src/public-video-watch.ts:109).
  • /page/:id is several actions behind one row: cached HTML, signed media JSON, readiness JSON, lead submission, and password unlock. The row claims every method; an unrecognized method can still render HTML (workers/frontend-router/src/public-page-delivery/index.ts:305).
  • /api/admin/accounts/search?format=csv streams CSV and writes an export audit row on GET (workers/frontend-router/src/admin-account-search.ts:76).
  • Uploads cannot be represented as an ordinary JSON operation alone. /api/media/upload-session brokers an R2 grant, /api/media/upload relays a byte stream and ETag, and new video bytes go directly from browser to Mux (workers/frontend-router/src/media-recording-sessions.ts:1, workers/frontend-router/src/router-endpoints.ts:497).
  • Provider signature verification needs the original body bytes before any JSON parse. Stripe then uses a durable inbox and cron retry; Mux intentionally has no dedupe table because its state patch is monotonic (workers/frontend-router/src/stripe-billing.ts:549, workers/frontend-router/src/mux-webhook.ts:30).
  • Product events often come from D1 triggers rather than handlers. Inserting a page emits journey_page_created; inserting a Library node emits folder_created or <kind>_added (workers/frontend-router/migrations-auth/0023_move_triggers.sql:13). Self-serve user insertion emits signup_completed (workers/frontend-router/migrations-auth/0013_native_accounts.sql:23).
  • defineOperation is currently an identity wrapper around an input schema and run. It has no output schema, HTTP mapping, side-effect declaration, or analytics field (workers/frontend-router/src/agent/operation.ts:36, workers/frontend-router/src/agent/operation.ts:63).
