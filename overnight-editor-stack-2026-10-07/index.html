What changed from last night's design

Last night's design page (https://willayam.github.io/clarity-design-previews/editor-panel-removal-2026-10-06/) proposed a typed edit core that the editor, the built-in AI and MCP all share. A Fable critique before the build changed the plan for tonight, and verification changed it further.

  • The editor did not need the edit core to lose the panel. Every canvas control still writes through the existing useEditorPage commands. The typed core, applyEdits in packages/journey-page-domain/src/page-edits.ts, runs on the server for pages_edit only. Moving the editor onto it is the next step.
  • Inverse edits were removed. Three verification rounds in a row found bugs in them, and nothing used them. Undo should be built on stored prior values instead.
  • Replay rules are simple. A batch applies in order against the current draft. An edit to a missing target is refused. An edit that sets a value is a no-op when the value is already there. Retrying the same call goes through its editId.
  • Existing data is never rewritten. A stored form field name, a stored seq_no and a stored block id each stay exactly as stored and stay addressable as stored. Only what an agent or a person creates gets fresh, unique values. Two early fixes had quietly renamed live form fields and reordered live pricing. The verifiers caught both and they were reversed.
  • Nothing was cut. Every control the panel had now lives on the canvas, the logos variant and colour settings included.

Bugs fixed along the way

  • The hero could be deleted from the panel, and then nothing could add it back. The hook now refuses to remove the hero, and the hero has no handle.
  • Canvas sections could not be moved, added or removed from the keyboard, and the only live region for move announcements sat inside the panel, which is inert when collapsed. The section handle fixes all three.
  • The canvas drag never stored its session, so unmounting mid-drag could not cancel it. Escape now cancels every drag.
  • Emptying a primary button's label also wiped its link (WIL-3295). The link and style now survive.
  • "+ Add field" could give two form fields the same name, and lead capture then dropped one of the answers. New fields take the first unused name, and stored names are never changed.
  • Duplicating a pricing plan could reverse its features, and an incomplete plan button could show on the page. Both fixed, and pricing order on the canvas now matches the published page.
  • Removing a repeated logo removed every copy of it. Logos are now removed by position, and every stored logo has its own control, even past the six the page displays.
  • The PDF frame, rolling logos and FAQ rows had controls a keyboard could not reach. All are reachable now.
  • The button settings card trapped keyboard focus in several paths. It now follows document order, stays in the viewport, and allows one open card per page.
  • Ghost "+ Add" controls were nearly invisible on dark themes. They now share one style in the page's own ink, measured at 13.9:1 to 17.9:1 contrast on the presets tested.
  • In the new agent write path, a form field named journey_page_id could have routed a prospect's lead into another workspace. Agents can no longer name fields, and the submission handler no longer lets a posted field override a server-owned value.

Not done, and follow-ups

  • #1024's dispatcher writes its replay record after the draft save. A retry that overlaps the first call can answer stale_position instead of replaying. This is in #1024, not in #1041.
  • Two helpers pick the next free form field name. They are nextCustomFieldName in the editor stack and nextLeadFormFieldName in #1041. The preview merge makes one delegate to the other. Whichever stack lands second should delete the duplicate.
  • On a short story image, the 80 px resize handle covers the Left alignment button. This is the same on main. Keyboard alignment works.
  • The rich-text link buttons are unreachable by keyboard. They behave the same in main's panel.
  • Form labels show an "Enter " prefix. A label stored as "Your first name" displays as "Enter Your first name" in the editor and on the public form. leadFormFieldLabel in packages/journey-page-domain/src/lead-form-fields.ts adds it. The behavior predates this work, but inline editing makes it visible.
  • A half-finished pricing button is hidden after a reload until it has a link. The label is kept, and adding the link brings it back. This follows the published page's rule.
  • Two Tab presses with no delay can skip the PDF buttons. Real key presses work.
  • The editor still saves whole documents. Next steps, in order: move the editor onto applyEdits, give list items durable ids and merge per item, then undo (WIL-3278). Folding EditableText into InlineText gives one text engine. The gallery drag and media resize should move onto beginPointerDrag.
  • Local pnpm lint does not run react-doctor. It prints a setup prompt, while CI runs it. Fix the local script so lanes see the same result CI does.
  • No usage data has been read yet. The rolling logos variant is the one cut I would consider after two weeks of usage counts on the new canvas controls.
