A Mux video lifecycle module owns "every asset has a node"

Strong ports & adapters reliability · privacy · cost

workers/workspace-tree/src/index.ts:943-953 · workspace-tree-store.ts:298-336 · mux-video-ingest.ts · mux-video-routes.ts:217-259 · mux-video-trim.ts · packages/mux/src/client.ts:63,185-216 · editor/src/lib/mux-recording-uploader.ts:34 · RecordVideoRoute.tsx:460-466 · packages/video-derivations/src/readiness.ts · scripts/mux-reingest.mjs

Before: five writers, no one owns the invariant

flowchart TB
  B[Browser recorder] -->|create node| T[tree index.ts]
  B -.->|90s timeout: second upload| M[(Mux)]
  W[Mux webhook] -->|node missing: 200, dropped| T
  D[Folder delete] -.->|children skipped| M
  S[reingest script on a laptop] --> M
  T -->|best-effort delete| M
  R[readiness.ts] -.->|legacy: preparing forever| B
  linkStyle 1,2,3,6 stroke:#dc2626,stroke-width:2px

After: one module, one interface

flowchart TB
  B[Browser] --> L
  W[Mux webhook] --> L
  C[Cron] --> L
  subgraph L[Video lifecycle module]
    direction TB
    a[create or adopt node]
    b[delete subtree and its assets]
    c[reconcile Mux against nodes]
    d[terminal readiness]
  end
  L --> M[(Mux adapter)]
  L --> DB[(tree D1)]
  style L fill:#0f172a,color:#fff

Problem. Mux assets outlive their nodes. Deleting a folder leaves every video inside it on Mux. Timeouts, retried POSTs and failed deletes add more orphans, and nothing ever finds them. Legacy videos that were never re-ingested show "preparing" forever and poll every 5 seconds.

Solution. Deepen the Mux code in workspace-tree into one lifecycle module. It owns node creation (the webhook can create a node from the upload passthrough, so a closed tab no longer loses the recording), subtree deletion with asset discard, a cron that reconciles Mux assets against live nodes, and a terminal readiness state for legacy videos.

  • locality: one module holds the Mux invariant
  • one interface, three callers (browser, webhook, cron)
  • tests hit one interface with a fake Mux adapter
  • deleting a video deletes it everywhere
  • Mux storage bill stops growing silently

The Journey Page content store owns revisions, tenancy and the list query

Strong local-substitutable data loss

workers/frontend-router/src/public-page-delivery/journey-page-content-store.ts:55-110 · journey-pages-native.ts:215-236, 334-397, 509-549, 684-711, 887-907 · editor/src/hooks/use-editor-page.ts:373-394

Before: the store is a pass-through upsert

route handler: read page, check access in JS
list: load all 6,946 pages, filter in JS
save: whole-document upsert, no revision
upsert sets deleted_at = null
tree card: fire-and-forget copy
owner_id in the column and in the JSON

After: one deep store

Journey Page content store

save(page, baseRevision) → saved | conflict | gone

list(owner) → SQL WHERE owner_id = ?

delete(page) → tombstone a save can't undo

inside: revision column, tenancy in columns only, card projection

Problem. Saves are last-write-wins. Two tabs, or an AI generation landing during autosave, silently overwrite each other. An autosave that lands after a delete brings the deleted page back, with its routes disabled and its Library cards gone. The page list reads every page in the database and filters in JavaScript, so it gets slower with every page any customer makes.

Solution. Put a revision column and a precondition in the store. Save returns a conflict instead of overwriting, and the save path never writes deleted_at. Tenancy moves into columns and the list becomes a scoped SQL query.

  • interface names the three outcomes
  • locality: tenancy decided in one place
  • tests run the store on real SQLite
  • list cost stops scaling with all customers
03

One module for access decisions, signed tokens and rate limits

Strong in-process security

workers/frontend-router/src/auth-session.ts · journey-pages-native.ts · public-page-delivery/index.ts · public-video-watch.ts · workers/workspace-tree/src/workspace-tree-store.ts · packages/auth-identity · wrangler.jsonc (rate limiter bindings)

Several concrete security findings came out of this lane, and two are high severity. They are with William privately, not on this public page. This card covers only the structural fix.

Before: each route decides for itself

flowchart LR
  R1[page routes] --> P1{{own predicate}}
  R2[public page] --> P2{{own token check}}
  R3[session cookie] --> P3{{own HMAC compare}}
  R4[tree decorations] --> P4{{own scoping}}
  R5[new route] -.-> X[whatever it remembers]
  linkStyle 4 stroke:#dc2626,stroke-width:2px

After: three deep modules

flowchart LR
  R[every route] --> A[authorize resource, actor, action]
  R --> T[verifySignedToken]
  R --> L[rate-limit table]
  style A fill:#0f172a,color:#fff
  style T fill:#0f172a,color:#fff
  style L fill:#0f172a,color:#fff

Problem. Access rules for pages, public pages, sessions and card media are written separately in each handler, with small differences. Token checks and rate limits are also per-route choices, so a new route can skip them.

Solution. Three modules. authorize(resource, actor, action) per resource kind, with explicit roles. One verifySignedToken for every signed token, plus a lint ban on a bare compare next to sign(. A route-to-limiter table, with a test that fails when an unauthenticated POST has no entry.

  • leverage: one policy, every route
  • tests enumerate actor × action
  • new routes are safe by default

One failure sink per runtime, and timeouts in each client adapter

Strong ports & adapters reliability

stripe-checkout.ts:192 · mux-video-routes.ts:252 · lead-capture.ts:111 · journey-pages-native.ts:531 · convex-spike/convex/generate.ts:256 · packages/mux/src/client.ts:191 · stripe-billing.ts:808 · workos-authenticate.ts · auth-email/src/send.ts:139 · packages/product-analytics-outbox · frontend-router/src/product-analytics.ts:36

Before: failures end in console.error

Stripe write failed
Mux event contended, 200
lead not linked
tree card not written
Convex generation failed
outbox poison row, forever

↓ Workers Logs, nobody watching

After

report(outcome) per runtime

Workers: Sentry SDK or a tail consumer

Convex: log stream

alert rule → a person

Each client adapter (Mux, Stripe, WorkOS, Resend) owns a default timeout. The outbox gets a dead state and pruning.

Problem. No worker or Convex function reports errors anywhere a person will see them. The external calls that matter have no timeout, so a slow Stripe hangs every navigation that goes through the trial wall. The analytics outbox retries permanent errors forever and never prunes delivered rows.

Solution. One reporting interface per runtime with an alert rule. Timeouts move into each client adapter so no caller can forget them. The outbox package gets a terminal state and retention, and the router cron gets the same per-source isolation as workspace-tree.

  • outages reach a person, not a customer
  • timeouts: one place per adapter

Top recommendation

01 · The Mux video lifecycle module

It's the newest code, it changes the most, and it protects both privacy and money: a deleted video is not deleted from Mux today, and Mux bills for every orphan. One module with one interface fixes deletion, lost webhooks, closed tabs and stuck legacy videos together. Candidate 06 (make the docs match the code) is small enough to ship alongside it.
