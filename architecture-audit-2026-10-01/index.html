Bottom line

Every lane reached the same verdict on its own: keep Cloudflare Workers, D1, R2, Mux, WorkOS, Stripe and Resend. The September work (the worker fold, the Convex removal, page and Library tables moved into one database) closed the topology gap. Nothing in the measurements argues for a different platform. The router does 15 ms of wall time per request, the public page renders in 15 to 43 ms of server time, and production threw 2 exceptions in a week.

What's left is the layer between the parts. Row types, request bodies, video state and Env are each typed by hand in more than one place, and nothing checks that the copies agree. The bugs that keep coming back live in two places where a hard problem is built from the wrong material. Document sync is a state machine hidden in nine React refs. Video lifecycle is a JSON bag in one text column. Fix those two, and make the schema the one source of types, and most of the recurring fix stream has nowhere to come from.

For the customer, the 30 Sept performance problems are mostly fixed. What's left is cheap. Images go out at upload size. The video start got slower when preload was turned off. One 325 kB player file is revalidated on every visit. And a rep can publish a completely blank page.

If we rebuilt it today

On the same platform, with these differences. Each one maps to a gap in today's code.

  • Data. One D1 database for accounts, pages, Library, jobs and mail state. Analytics stays separate. Migrations are the source of truth and row types are generated from them. Tenant-scoped tables have (workspace_id, id) keys and real foreign keys. Lifecycle state lives in columns with CHECK constraints, copying the jobs table, which is the best schema in the repo. Today: one physical database with two binding names, 92 hand-typed reads, almost no foreign keys, video state in JSON.
  • API contract. One route table. Each row declares path, method, audience, entitlement, origin policy and rate tier, and dispatch, the trial wall and the origin guard are generated from it. Bodies and provider payloads are parsed at the edge, and handlers get a parsed context with identity already resolved. The editor imports the response types. Today: about 30 ordered decisions in index.ts, plus separate path logic in the wall, the origin guard and the auth table. The editor's apiRequest<T> casts every response, and its own comment says a 200 can carry an error.
  • Client state. TanStack Query owns everything remote, including writes, and mutations return the committed revision. The editor document lives in one plain store with a named save state machine, which React subscribes to. Today: 24 queries, 0 mutations, plus a session cache, a sessionStorage user, a warm-root promise map, custom events and a node overlay.
  • Rendering. String SSR for prospects and React for reps, sharing the block registry, CSS and a typed block view model. Same as today minus the legacy step-media translation. Not a unified renderer (see "Dismissed").
  • Video. Mux, with typed videos and video_clip_jobs tables and one module that owns every transition. The browser expresses intent and never names server fields.
  • Jobs and providers. The jobs pattern extended to a provider-event inbox (Stripe, Resend, Mux) keyed by event id, and a cleanup and send outbox written in the same batch as the business change, both drained by the one-minute cron. No Queues and no Durable Objects at this volume. A table you can SELECT beats a queue you can't.
  • Deploy. Build once, promote the artifact, one plan generator called by both the workflow and just. Today the same policy is spread over about 1,475 lines in four dialects.

The highest-leverage move

Make the migrations the one source of row types, and route every D1 read through them. A script applies migrations-auth to in-memory SQLite, reads each table's columns and writes the row types. A lint rule then forbids a type argument on .first or .all that doesn't come from that generated module. The hard half already exists: six test helpers apply the real migrations in Node today. Converting the 92 reads is mechanical and checkable, which is the kind of work agents do well and a human can review fast.

Why this first. It turns the next three moves into schema edits instead of risky changes. The typed videos table (WIL-3494), composite tenant keys and foreign keys all become changes the compiler follows into every reader, not a hunt for every hand-written row interface that silently disagrees. Opus picked this move. Astra picked the video lifecycle module and Fable picked a real package graph. I side with Opus. WIL-3494 is already in flight and gets cheaper with generated types, and the package graph lost most of its urgency when its headline bug turned out not to be live.

In parallel, because it's where the fixes land: move the editor's document session out of React into one store with a named save state machine (idle, saving against revision N, conflict, adopting) and a single serialized writer. All three critics ranked this the costliest error class. The nine refs exist because hook state can't express "exactly one save in flight against revision N". A store can. The accepted merge rules (later save wins per field, edit beats delete) stay as they are.

Corrections, dismissals and disagreements

  • Stale production bundle, downgraded to latent. I first confirmed that the build fingerprint covers only 3 of the 11 packages the editor imports. Astra then pointed out that the deploy script puts the commit SHA into the fingerprint, so every new commit builds fresh. The hole only bites a direct build without those variables. Fable and Opus had both ranked it on my first reading. The real lesson runs the other way: the cache is mostly dead weight.
  • "48% of page cards in the wrong tenant", overstated. 6,015 of the 6,024 cards were in one QA workspace, and the rest followed from a deliberate design change. Composite tenant keys are still worth doing, on the merits of class 8.
  • Renderer unification, dismissed. The canvas and the SSR already share the registry, CSS, layout, theme and sanitizers. Unifying them would pull editing affordances toward the Worker for no customer-visible gain. Delete the step-media adapter instead.
  • Test adapter consolidation, low priority. Every SQLite helper already applies the real migrations, so merging them is tidiness, not risk reduction. Their real value is as the base for type generation.
  • Geography, not a config fix. Smart Placement is already on. Per-colo TTFB rests on 75 events, so treat it as a direction only.
  • Kept, praised by all three critics. The jobs table (fenced leases, CHECK states), idempotent publish per revision, page delete as one batch, CAS metadata writes, the analytics outbox, and decideEntitlement as the one access rule. Copy these rather than replace them.
