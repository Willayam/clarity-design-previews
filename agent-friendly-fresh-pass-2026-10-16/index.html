The agent kernel (C10), designed three ways

This class ranks first: 43 mistakes, all since 10-05, several of which put passwords in answers or published without approval. Three models designed it independently (fable-5.1, gpt-6-astra, opus-5.5). A gpt-6-astra cross-judge then checked their claims against all nine fix diffs.

Two of the three converged on one shape. An operation file binds a tool name to a command owned by the store, and supplies no run code, approval facts, exposure, replay check or answer mapper. The command's proposal is a list of consequences. Each consequence records what the owner reads, which stored values it relies on, and the check that runs inside the write. The card, the stale digest and the guarded write all derive from that one list. Answers go through a private projector, and secrets never enter a snapshot.

This is #1493's direction ("one definition per action and per invariant"), so the plan amends #1496 to #1499 rather than starting a parallel program. Concretely: extend the action kernel from #1495, retire the unused action.plain and action.approvable builders, and keep conditional D1 batches. Library and pages share one database in-process, so the reservations one candidate wanted aren't needed. Of the nine pinned fixes, the base design makes four unrepresentable or type errors and the other five fixes in one place. These are design-level verdicts, not compiled.

Update 10-19. The MCP surface has no users yet

You said the MCP project is greenfield, so it should be right the first time. Production /mcp answers 503 not_configured today (checked 10-19), and the agent sign-in issuer is set only on staging. So no outside caller depends on any tool's shape. The browser editor does have users, and stored D1 data does too. Those constraints stay.

A fresh lane re-read #1493 to #1506, the agent code and this plan for anything kept only so the MCP contract wouldn't change. The code itself carries no aliases, deprecated fields or versioned tool names. The cost sat in the plan: the arena brief and rubric required the MCP input to stay unchanged, the winning design added a map from command field names back to today's argument names, the RowId rule kept seqNo as an alias for one release, and call 1 defaulted to the old contract. #1493's design text also calls MCP "the public contract". All of that is now dropped. The changes:

  1. One staleness rule for agent writes. Exposure binds to what the agent read. Draft edits apply to the latest draft. So pages_publish requires revision as #1497 says, and refuses a moved draft with stale_revision before asking the owner. If the live link already serves that revision, it answers the URL with no approval. Today no agent tool checks against what the agent itself read, so an owner's later autosave can be published without the agent having seen it.
  2. Drop pages_edit.baseRevision. It has been required since 10-06 and nothing checks it. Its only use is as a fallback number inside a refusal (ops-pages.ts:368). An agent reading the schema would believe it guards a stale read. It doesn't.
  3. Address rows by RowId only. pages_edit addresses list rows four ways today: id, seq_no, field_name, and position plus a content snapshot. 28 of its 38 variants address a row. Use the RowId for FAQ rows, plans, features, form fields and summary rows, and the asset id for gallery and logo images, which is already unique per block. seq_no stays the stored order and field_name stays the lead key, but neither is an address any more. The edit-op language has only agent callers, so this deletes about 150 to 200 lines of alternate paths outright. Summary columns keep position, since they aren't rows.
  4. Command fields are the tool's argument names. The C10 base design loses its field map and the test that compares generated schemas with today's. The tools/list size budget and the evals stay as the gate.
  5. One refusal vocabulary where the concept is shared. The agent door uses the browser's stale_revision and stale_approval instead of its own stale. Agent-only concepts keep their codes.
  6. Each action's output is designed once for both doors. #1495 copied the MCP output shapes of settings_get and pages_stats verbatim and built a fake agent caller to reuse them. The cheap moment to reshape a tool is the PR that moves it, before the editor starts calling it through act(). After that, open tabs pin the shape.
  7. Delete the MCP legacy half when the last family moves. The second tool list and the second approval executor are a migration bridge, not caller compatibility. They go in the PR that empties the old registry, not in PR 13. The two-week log window in PR 13 protects browser tabs only. Pending staging approvals for a moved operation are failed at deploy instead of kept readable through a fallback.

Where each lands: 1 in #1497. 2 and 3 in #1500, which moves pages_edit into the kernel, together with a regenerated pages_edit_help. 4 to 7 in the kernel amendment to #1496 to #1499. Each PR updates its in-repo consumers in the same change: the eval fixtures, scripts/agent-mcp.mjs, the CLI upload command, the verify-loop agent doc and the /agents page copy. The eval baseline (383 of 385 passing) is the gate. Nothing here was compiled. The sizes come from grep counts and the 10-16 RowId prototype.

What RowId still costs is outside MCP. Normalize must assign and de-duplicate ids. Ids must be stored before an agent relies on them across calls. The backfill must not bump the draft revision, or every live page shows a draft ahead of live. And the editor must round-trip row ids, so a stale tab's autosave doesn't erase them. That is the 31 type errors in 8 files and the 15 rowKeys calls already counted.

The plan

Wave 1. Static checks proven on past fixes (S each, this week)

  1. Extend "drops the answer" to updateWorkspaceTreeNode, updateJourneyPage, the draft savers, the brand logo writers and the recorder save, including console-only .catch (C11).
  2. Refuse suppression growth for any rule that already has a baseline (C14). Make the proof-head step fail its job again.
  3. Rerun the migration-number check on push to main, and refuse the deploy on a clash (C4).
  4. Fence video state reads to video-readiness.ts and served-file-policy as a shrink-only ratchet from 16 files (C9). The projection gains settled, so caches stop deriving it.

Wave 2. Architecture with a proven test (M each)

  1. The document store owns the focused draft (C1). Text components stop holding field text, focused-canvas-draft.ts and sync-editable-text.ts are deleted, and the seeded interleaving test lands with it.
  2. One editor sign-in exit (C6). It checks the current path just before navigating, sanitizes the captured target and owns /login. The API 401 handler and the protected layout both call it.
  3. The agent kernel amendment, delivered inside #1496 to #1499 (C10).

Wave 3. Larger moves, sized by the prototypes

  1. List row ids assigned and de-duplicated at load, then required. The agent addresses rows by id only, with no alias, and row-keys.ts is deleted (C2). This touches 31 type errors in 8 files and 15 rowKeys calls. It ships in #1500 with the pages_edit move.
  2. Presentation rules for blocks whose editor and public output have diverged, as pure functions in journey-page-domain. Start with pricing (C3).

Not yet proven, so not in a wave

  • C5 parsed external clients plus a ratchet on as Type and JSON.parse (about 254 and 63 on main). This needs the same replay before it earns a slot.
  • C7 finish the access-field lint (3 admin files). This is small but wasn't prototyped.
  • C12 one inline field, one play control, dialogs only through ui/dialog. This class has the most rows but costs the least, and the change is large.
  • C13 a statement-counting helper to replace the 13 new inline disables of the query-text-fake rule.
