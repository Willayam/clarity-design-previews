Bottom line

Yesterday's fixes worked where they finished. The editor save hook took 10 fix commits before the document store and none since. Stripe webhooks can no longer be acknowledged and lost. Database reads are typed from the migrations. A prospect's tap now starts the video in about 150 ms.

Several of them stopped one step short, and that step is where today's defects are. The typed videos table exists and reads go through it, but every write still goes to both the row and the old JSON, and in production the new lifecycle code produces effects that are all thrown away. A real job table sits beside a second job queue written in JSON. An index built for sweeping unfinished videos has no reader. The document store has two writers still outside it. The access rule works out why an account is walled and the wall ignores the reason.

All three critics picked the same next move without seeing each other's answers: finish the video handover and delete the double write. They also agree on the stopping point. There is about one to two weeks of structural work left that pays, most of it ending in deleted code. After that the return is in the product, and the commit mix says so too. Since 25 September there are 106 fix commits and 61 feature commits.

The highest-leverage move

Finish WIL-3494 and delete the double write. Hand share pages and clips to the take's reducer batch, move clip work into the jobs table, sweep unfinished videos from the one-minute cron using the index that already exists, then delete the JSON projection, the read overlay and the parity test, in that order.

Why this one. Library video has 49 fix commits since 25 September and about a dozen since last night, while every other hot area went quiet. It is the only item that gets more expensive by waiting, because production now reads through an overlay that falls back to the old JSON without telling anyone when a row fails to parse, and every day adds takes created inside the double-write window. The destination code is already written. And it is the only candidate that ends with less code, somewhere between 600 and 1,000 lines counting the parity test.

It beats the route table (WIL-3401) because that surface produced 11 fixes against video's 49, and it is waiting on answers to five questions. It beats a shared API contract package because that class does not show up in the fix history. It beats unifying the deploy scripts because they work.

One disagreement. Opus says holding the current position is the most expensive option, so either finish now or revert the read flip. Fable and Astra say revert nothing. I side with finishing. The ticket is in flight and the remaining steps are named in the code.

On the cache window: raising 60 seconds is a trade, not a free constant. The cache key holds the publication revision, so publish, unpublish and delete are immediate at any window. A trim or a new poster does not change the key, so the window is also how long a prospect can see the old video. Ten minutes is defensible. An hour needs a media version in the key.

What would make the app feel instant: the shell paint in row 4, mutations that return the committed revision so Home and the editor can update first and confirm after, and listings that stop waiting on Mux (up to three checks of two seconds each) once the cron sweeps unfinished videos.

If we rebuilt it today

The same platform, and nearly the same design. Workers, D1, R2, Mux, WorkOS, Stripe, a leased jobs table drained by a one-minute cron, string SSR for prospects and React for reps. The router spends 1.7 ms of CPU per request at p50 and threw 1 exception in 121,268 requests this week. Nothing in the numbers argues for different parts.

The gap is no longer a list of things to build. Most of the target exists in the repo as working code with one connection missing:

  • The video reducer exists, and production discards every effect it produces.
  • The jobs table has a clip kind with a lease policy, and clip work runs from a JSON object with its own leases, attempts and backoff.
  • An index for unfinished videos exists, and listings still ask Mux inline.
  • The document store exists, and two writers sit outside it.
  • The import graph is computed and tested, and the browser check is chosen from a hand-kept list.
  • The access rule returns a cause, and the wall prints one message.

Two pieces of the ideal are not started: one route table with parsed config (designed, waiting on answers), and request and response types shared by the editor and the Workers (35 casts today, no fix history against them). Neither is worth starting before the six connections above are made.

When to stop

After one more wave. Finish the video handover and delete the double write. Give the recorder a per-take store, starting with a flush() that tells the truth. Move the share dialog onto the document store. Pick browser checks from the import graph. Delete Resend on 9 October and the dormant tables after the 8th. The critics put this at one to three weeks, and most of it removes code.

Then stop auditing. This is the sixth pass in twelve days, and the editor hook going from 10 fixes to 0 says finishing a migration pays more than finding the next one. A seventh pass before the video double write is gone would mostly repeat this one.

Corrections, dismissals and disagreements

  • My fix counts were wrong for an hour. A bug in my counting command reported every commit touching a file as a fix. The router entry file has 5 fix commits since 25 September, not 29, and the two deploy scripts have 8 between them, not 38. The synthesis lane caught it. The corrected counts put the cost in Library video (49) and the editor save path (33), which is where yesterday's work aimed.
  • "One confirmed contract drift" is not drift. The synthesis reported a card preview kind present on the server and missing in the editor. Astra pointed out the router converts it before the response leaves, and the code confirms that. The seam is still held by a string comparison, which is an argument for typed Library results.
  • The cache header on a hit overstates its window. A hit reports s-maxage=14400 while entries reset at 60 seconds. Harmless today, misleading to anything downstream.
  • Slow lab requests were my network. About 4 in 60 probes waited 1 to 4 seconds in TCP connect while the Worker answered in 15 ms. The measuring machine drops IPv4 connects. I did not rank it.
  • Left alone on purpose. Publish then route activation is two steps with a stated, convergent retry. The public page inlines about 56 KB of CSS and script that compress to about 20 KB with nothing render-blocking. The readiness endpoint returns rendered HTML, which is fine for a string-rendered page. The availability read on every cache hit is the invalidation design.
  • Where the critics split. Opus would revert the video read flip if the handover is not finished now. Fable puts the remaining structural work at two to three weeks, Astra and Opus at about one. Fable would unify the deploy scripts. Astra and Opus would not yet.
  • Worth copying, named by all three. The jobs table, the Stripe inbox, the revision-keyed page cache, the row-type lint rule, the import graph in deploy-plan.mjs, and the document store.
