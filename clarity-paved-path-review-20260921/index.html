01 · Strong · start here

Make Library mutations own freshness

A caller can move a node and get invalidation automatically. Create, update, and delete leave that responsibility to callers. Screens and folder helpers repair the gap with their own change signals.

Make the existing mutation module own successful-write signaling. Remove the duplicate signals from callers in the same change. Keep the existing query invalidation subscriber initially. This gives the module more depth without adding another layer.

Proof. Exercise create, rename, move, and delete through the public mutation path. Failed writes must not publish success. Storage failure must not prevent live invalidation. Today, storage and event dispatch share one try block.

Completion. A caller awaits its operation and has no second freshness step. Preserve intentional batching, upload reconciliation, and node-type filtering. Locality improves because a cache rule changes in one owner.

TodayScreen → mutation → remember dirty signal → query subscriber
TargetScreen → mutation that owns its change signal → query subscriber

03 · Strong · next domain cleanup

Give completed videos one acceptance client

Recordings and file uploads call the same acceptance endpoint separately. The file path expects a Workspace node. The recorder accepts several envelope shapes and substitutes the upload session ID when the node ID is missing.

Use one strict acceptance client for both flows. A completed-video result requires its verified upload receipt. Image and document results keep their own shape. The server remains the authority for receipt verification and idempotency.

Completion. One browser implementation of the acceptance route. Delete speculative envelope parsing, the ID fallback, and duplicated completed-video shapes.

Proof. Preserve recording metadata and posters, retries, file-upload cancellation, queue reconciliation, and recovery. Recorder acceptance still precedes a metadata PATCH. Sharing the client does not make those writes atomic.

Payoff. Callers learn one acceptance contract. Tests pin that contract once and exercise each caller’s distinct lifecycle.

TodayRecorder parser + file-upload parser → same server endpoint
TargetRecorder + file upload → one acceptance client → server

Move root prefetch into that existing owner. Keep session persistence as an implementation detail until measurements justify changing it. This is a separate change from mutation ownership.

Proof. Preserve early network start, parallel folder and media requests, account-scoped keys, and fast cached paint. Test a mutation racing an in-flight prefetch. The current query functions do not appear to consume cancellation signals, so invalidation alone is not proof.

Completion. Delete the second promise map and its coordination warning after the race tests pass. Callers no longer need to know which cache served the data.

Make each cleanup prevent its own return

  1. Choose the owner and migrate its actual callers. Prefer the existing module when it can own the responsibility.
  2. Delete the old path in the same change. A second supported entrance leaves future authors another choice to get wrong.
  3. Make the type require the information the operation needs. Validate network data at its entry point.
  4. Add a narrow import restriction only where the migration establishes an internal module. Keep safe public mutation imports legal. Do not create barrels merely to satisfy a global rule.
  5. Test the caller-visible contract. Completion means fewer rules to remember, fewer duplicate decisions, and no abandoned path.

Existing ESLint checks already enforce UI primitive reuse and guarded-write results. Extend that mechanism where it protects a proven owner. A blanket comment ban would remove useful explanations without fixing responsibility.
