Accounts, access and support: synthesized target design

Base: the Opus candidate. Grafts from Fable and Astra. Fixes from the cross-judge. Origin/main 4ccbfdd1, 2026-09-30.

The rule

A person can use Clarity when Stripe says they are paid, or they hold an access grant that has not ended, or they are staff, and no hold is on the account. One pure function decides it. Each fact it reads has exactly one writer.

Fact Where Only writer
Identity users (id, workos_user_id, email, names, owner id) sign-in, provisioning, admin email change
Staff users.system_role admin command set_staff
Hold users.suspended_at + reason + by; account_deletions row admin commands, self-serve delete
Grants access_grants provisioning, offers, admin commands, migration runs
Stripe mirror stripe_subscriptions syncStripeSubscription only
Memberships organization_memberships admin commands, offers
Audit admin_actions runAdminCommand in the same D1 batch as the write

Deleted: users.kind, users.status, users.expiration_date, users.role, users.legacy_corp_id, users.legacy_affiliate_id, the old subscriptions table, support_invitations, the window-claim marker. Legacy ids on organizations stay as inert import provenance, because their UNIQUE constraints cannot be dropped without a rebuild.

Access decision

// packages/auth-identity/src/access.ts. Pure.
export type Grant =
  | (GrantCommon & { kind: 'trial' })
  | (GrantCommon & { kind: 'included'; payer: Payer; note: string })
  | (GrantCommon & { kind: 'complimentary'; note: string; stopsBilling: boolean });
export type Payer = { kind: 'organization'; organizationId: OrganizationId; name: string } | { kind: 'named'; name: string };

export type AccessFacts = {
  now: Instant;
  staff: boolean;
  hold: Hold | null;                       // suspended | deletion_scheduled
  grants: readonly Grant[];                // ends_at NOT NULL; nothing is open-ended
  stripe: readonly StripeSubscription[];   // Stripe status verbatim
};

export type AccessDecision =
  | { access: 'blocked'; hold: Hold }
  | { access: 'allowed'; basis: 'staff' }
  | { access: 'allowed'; basis: 'covered'; coverage: Coverage; alsoCovering: readonly Coverage[] }
  | { access: 'walled'; cause: 'trial_ended' | 'grant_ended' | 'subscription_ended' | 'payment_failed' | 'never_covered'; since: Instant | null };

export function decideAccess(facts: AccessFacts): AccessDecision;
// active | trialing: until min(period end, cancel_at); no period end = not paid.
// past_due: until period start + PAST_DUE_GRACE_DAYS (7). Everything else: not paid.
export function paidThrough(sub: StripeSubscription, now: Instant): { until: Instant; renews: boolean; pastDue: boolean } | null;
// Checkout guard asks this, never the winning basis, so a paying staff member cannot double-subscribe.
export function hasRenewingSubscription(stripe: readonly StripeSubscription[], now: Instant): boolean;

Order: hold, staff, coverage, walled. A hold beats staff so a compromised admin can be switched off. The command policy refuses suspending yourself, removing your own staff role, and removing the last staff member.

Where it is enforced

resolveSession loads identity, hold, staff, grants and Stripe rows in one D1 batch on every request, then calls decideAccess. A D1 error is a 503, never "allowed". No identity row means no session. The two fail-open branches of today's wall go away.

  • App gate (replaces trial-wall.ts): blocked and walled sessions see one page with one message per cause. Wall exits stay open: checkout, portal link, unpublish, delete page or video, export, delete my account, sign out. Holds get no exits except sign out.
  • Admin API: requireStaff(session), refusing impersonated sessions.
  • Money and identity self-service (checkout, portal, export, delete): requireOwnSession, refusing impersonated sessions.

Stripe

The webhook is a doorbell. It verifies the signature, extracts the subscription id, and calls syncStripeSubscription, which fetches the subscription and upserts stripe_subscriptions. Order and duplicates stop mattering. A fetch older than the stored synced_at is dropped and triggers one more fetch. A subscription Clarity cannot link is stored with user_id NULL and listed for Ace, never retried forever. The nightly scheduled() refresh lists every Stripe subscription. The same function serves the panel's Refresh button and the wall page.

The nightly refresh also converges intent. For every live complimentary grant with stopsBilling, if the user still has a renewing subscription, it sets cancel_at_period_end. So "make complimentary" protects access at once and billing stops even if the first Stripe call failed.

Admin portal

One account panel. Its top line is a sentence from accessHeadline, such as "Can get in until 31 Jul 2027. Included, paid by the Boardroom sponsor. Last changed by Ace on 2 Oct 2026." Below it are Access (every grant and subscription, with alsoCovering), Organizations, Staff, History, and a Danger zone.

Three routes: GET /api/admin/accounts?q=, GET /api/admin/accounts/:id, POST /api/admin/commands. Every write is an AdminCommand (a closed union) run by runAdminCommand: parse, load before, pure refuseCommand, apply, audit in one batch. The command id is the audit key, so a double click replays.

Customer Admin self-serve later is a second Actor variant with a narrower refuseCommand branch over the organization commands.

Boardroom

/boardroom links to /join/boardroom. A signed-in visitor gets the offer applied. A new visitor carries a signed 30-minute cookie through AuthKit, and provisioning applies it once: a 10-month included grant paid by the existing Boardroom organization, plus membership. signup_completed carries offer: boardroom. The page is noindex. Ace reviews the organization list against the sponsor's roster and uses renew_included_access when the sponsor pays a period. A GoHighLevel sync, if revived, reads grants and memberships and never grants access.

Organizations

Membership is the only organization link. A membership grants nothing by itself. It tags, names a payer, and carries customer contact sharing (re-keyed from legacy_corp_id, so about 60 users see no change). Journey-page sharing by corp or affiliate id is deleted. Organization-paid seats, later, would add organization_id to stripe_subscriptions and count as coverage for members.

End of life

request_deletion places a 7-day hold, then an idempotent purge walks each store (Stripe, public pages, workspace media and Mux, contacts, auth email, PostHog, WorkOS, identity row last). The users row stays as a tombstone with a scrubbed email so the address can sign up again. Export uses the same store list read-only.

Migration order

Each step is one PR or one data run with its own proof. The census (read-only, extending scripts/account-spine-entitlement-diff.mjs) computes the old and the new decision for every prod user and lists each flip by class. It gates every step. It runs from a scratch checkout and stays off main, since merged code only guards what CI runs.

  1. Safety PR. Wall exits for takedown. Extend refuses corporate and internal accounts and any date earlier than current access (the period end for a paying account). Dates end at the end of the day. Delete Activate, its endpoint, the dead Extend guard, and "Cancel free trial" where no Stripe subscription exists. Refuse billing writes from impersonated sessions. noindex on /boardroom.
  2. Census and Stripe diff, data run. The census script against today's rule. The Stripe diff lists every Stripe subscription against D1 and classifies it as linked fresh, linked stale, unlinked with owner hint, or no match. This feeds WIL-3433 and the decision on the 72 recorded subscribers. It needs a read-only Stripe key.
  3. Grants PR. Add access_grants and admin_actions. The migration backfills a grant per future expiration_date. decideEntitlement gains one independent rule, that a live grant allows whatever the kind, and keeps reading expiration_date as a legacy source until step 6b, so a write in the deploy gap is never lost. Signup, invitation acceptance and Extend write grants. Stripe events stop writing kind and expiration_date, which ends the comp-erasure bug. They keep writing status = inactive on cancellation until the recorded-subscriber rule dies. Extend becomes grant_access through runAdminCommand, with audit. Census proof: zero flips.
  4. Boardroom PR. The offer route, cookie, provisioning hook, noindex kept, and the organization list filter with CSV and "ends within 30 days". Ace grants early signups by hand.
  5. Account panel, holds and staff PR, after William names the staff to keep and a logged data run clears the rest. Adds resolveSession as the one fail-closed batch, holds, the staff bypass, search, the panel, History and the account commands. Deletes the row menu, the billing dialog, the old admin endpoints, WorkOS invitations and their UI.
  6. a. Stripe mirror PR and data run. stripe_subscriptions, the doorbell webhook, the nightly refresh with intent convergence, the unlinked list, Stripe commands and make_complimentary. The old subscriptions rows keep being written for one release. The data run compares the mirror with the old rows. b. Cutover PR and data run. Convert the legacy classes per William's answers, idempotent by source. decideAccess takes its final form. Delete the exempt and recorded-subscriber rules, the expiration_date read, the old sync, and every Stripe write to users. Merge gate: the census lists every flip, and each belongs to a decided class.
  7. Organizations PR and data run. The organization page and commands. Memberships become the only link. Delete the organization billing stub.
  8. End of life PR. Export, deletion, the tombstone, and the new-mailbox confirmation on email change.
  9. Drops PR, after 5 to 8 are live. Drop the users columns, the old subscriptions table and support_invitations. Legacy organization ids stay.

Grafts and rejections

  • From Fable: the census as the permanent proof, run at every step; reasons only where they matter; the explicit panel contract.
  • From Astra: impersonated sessions refused for money, identity and privacy; an explicit takedown command instead of "impersonate and click"; new-mailbox proof on email change; never evicting uncertain legacy access without review.
  • From the cross-judge: a named payer without an organization; the checkout guard asks about renewing subscriptions, not the winning basis; grants count independently of kind during the transition; the legacy date stays a source until cutover; complimentary intent converges on the nightly refresh; legacy organization columns stay.
  • Rejected from Astra: fenced leases, reconciliation generations, the operations queue, preview-then-confirm tokens, session versions, subscription schedules, user merge, staff grants. Each solves a failure mode that 164 subscriptions and one support person do not have, and together they would double the new surface. Session versions come back only if forced sign-out without suspension is ever needed.
  • Rejected from Fable: keeping WorkOS invitations as offers by email; a column-extended subscriptions table, whose CHECK constraints block the later drops.
  • Cross-judge note: the judge ran on the same model as the Astra candidate and ranked it first. Its defect findings were checked against the code and adopted; its base pick was not.
