Agent-friendly architecture: plan

Clarity repo, plan phase only. Written 2026-10-04 against origin/main 346c85da7. Nothing here has been pushed, ticketed or deployed. Store: ~/.claude/orchestrate/agent-friendly-arch/ (data tables, scripts, prototype results, decisions.tsv).

What this is for

Agents write most of Clarity's code now. Since 1 July 2026, 1,688 commits landed on main; 267 were fix-shaped, and the fix share rose from 16% of September's commits to 26% of October's. 184 of those fixes landed within four days of a feature commit on the same file. This plan names the mistake classes behind those fixes, with counts and evidence, and proposes repo changes that stop each class at the highest level that works: architecture first, then types, then a lint whose error names the fix, then a test, and prose last. Each proposed change is a PR-sized unit with a verify command and a deploy-safety tier.

For William, the payoff is fewer follow-up fixes per feature and fewer corrections typed into agent sessions. For the next agent, it is a repo where the shortest path that compiles is the right one.

1. video-lifecycle (80)

Evidence. The single feature commit with the most follow-up fixes in the window is 834286e75 "create a video node from an upload that is still in flight": 24 fixes in the next four days, among them 0e9643e2d (fence the settle write), 092202728 (settle processing takes from the daily Mux list), f669df502 (two concurrent reads count one settle miss), 328355d78 (recorder blocked by backoff). Linear: WIL-3426 (deleting a video leaves Mux assets), WIL-3441 (17 s saves and duplicate nodes), WIL-3459 (Mux fields browser-writable on legacy nodes), WIL-3453 (clip failure invisible). workers/workspace-tree/src and its tests took 291 fix-file touches, the most of any directory.

Root structural cause. Video truth lived in three places (Mux, a JSON metadata bag, the browser) and readiness was asked and settled from several readers with no single owner of state transitions. The lane's causes read "settlement depended on someone reading the take", "selection and reducer writes were separate", "field lock inferred from presence of optional fields".

Candidates.

  • A. One lifecycle module owns every write to video state; every other module asks it. The server-owned recording lifecycle program WIL-3494 is this candidate, and PRs through #4 have landed. A lint confines SQL on the videos table to that module.
  • B. Enforce legal transitions in D1 with CHECK constraints and triggers only, leaving writers where they are.
  • C. Add a reconciler cron that repairs whatever the writers leave inconsistent.

Screen. B fails because settle backoff and "asked Mux at read time" are not expressible as row constraints, and it leaves split ownership in place. C is the pattern that produced 24 follow-ups: a second writer. A passes; it is the deep module.

Prototype. Census on origin/main: UPDATE|INSERT|DELETE on videos appears in exactly two files, workers/workspace-tree/src/video-row.ts and mux-video-ingest.ts. A boundary lint holds with zero violations today, so it only has to stop regressions.

Decision. Architecture (finish WIL-3494 PRs 5 and 7 and delete the dual write and JSON fallback, as the 2 Oct audit's unanimous verdict said) plus the boundary lint now. Units U4, U13.

2. styling-design-system (44)

Evidence. WIL-3386 (password toggle built twice on Input), WIL-3384 and WIL-3385 (stacking keyed on viewport width instead of container width), WIL-3382 (no layering contract for stacked overlays), WIL-3291 (backdrop-filter without the webkit prefix, since made a lint), 31 fix commits in the editor's components. eslint-suppressions.json still carries 358 violations across 51 files.

Root structural cause. Two authoring modes (CSS partials and utilities) and primitives with gaps that callers patch individually. The styling audit of 2026-09-15 covers this class and its verdicts are still open with William.

Candidates. A. The existing ratchet, tightened: a file in the suppressions baseline that a PR touches must leave with a lower count. B. Finish the CSS to utilities migration. C. Parity test per block kind between the two renderers.

Screen. B is a program, not a unit, and William asked for lint over harnesses when the migration arrived with 36k lines of rig (PR #737). C guards renderer-parity (2 items) and belongs to the styling audit. A is small and compounds.

Decision. Lint ratchet, unit U16. Nothing else from this class is in scope here.

3. auth-identity (37)

Evidence. eee141ecb (an ended grant still allowed access: entitlement had access_grants and users.expiration_date as competing sources), 147b1f6b2 (admin endpoints used different identity checks), f6d935248 (unlock token not bound to the password), WIL-3489 (Mux webhook missing from a hand-maintained origin-guard exemption list), WIL-3511 (each public POST wires its own rate limit and compare), b27ecdf3e (Referrer-Policy produced Origin: null and the mutation guard refused lead forms for 24 days).

Root structural cause. Policy is wired per handler in an ordered if-chain router (workers/frontend-router/src/index.ts, 869 lines), so every guard is a list someone has to remember, and entitlement had two sources of truth until decideEntitlement.

Candidates. A. A route table where each route declares its policy (auth, rate limit, origin guard, body cap) and one dispatcher applies it; WIL-3401 scoped to policy as the 2 Oct audit recommended. B. Keep the if-chain and add a lint that bans the raw guard calls outside a wrapper. C. Middleware chain per route group.

Screen. B leaves the hand-maintained lists (exemptions, caps) in place; it stops one shape of mistake, not the class. C is a pass-through layer that still lets a handler skip the chain. A passes and also removes the "HEAD answers 404 while GET answers 302" shape (WIL-3505).

Prototype. Reads of expiration_date or legacy users.kind comparisons outside the entitlement module: 7, in two files (account-profile.ts, admin-accounts-native.ts). A lint confining those reads is a 7-line cleanup.

Decision. Lint now (U6), route table as a Tier C unit (U14) because it touches the auth path and William asked to sign the design.

4. editor-save-state (35)

Evidence. 7dc906a7f "hold the stored draft revision and send it with every save" drew 17 fixes in two days: 33ca436da (make create idempotent on an editor-minted id), 9659a417d (refuse a stale whole-document save), 6ddbf897c (adopt a landed draft only after the editor's own saves answer), 4c5d11730 (saves never settled). Linear WIL-3515, WIL-3524, WIL-3411.

Root structural cause. Draft state was owned by React refs in the client and the server accepted last-write-wins; the create was not idempotent. The 1 Oct audit called the editor store the costliest class and it has since landed (use-editor-page.ts went from 10 fix touches to 0).

Candidates. A. One client store owns the draft and one server endpoint owns writes, with a revision precondition the server enforces on every page write. B. Client-side supersession guards only (the shape WIL-3285 calls check-then-write). C. CRDT or sync engine.

Screen. B is where the 17 fixes came from. C was rejected on evidence in the 2 Oct audit. A passes.

Prototype. Calls to page or tree write endpoints outside editor/src/lib/editor-api.ts and tree-api.ts: 0 today. The boundary exists in practice and only needs a lint to stay.

Decision. Lint now (U5), server precondition as Tier B (U12).

6. deploy-config (24)

Evidence. Previews inherited production bindings or values five separate times: WIL-3176 (previews bound production D1), WIL-3360 (production R2 broker), WIL-3431 (84 analytics rows written to prod), WIL-3488 (production media key and signing secret), WIL-3517 (production Mux Data). WIL-3472 and 0d9385b21: the production MUX_WEBHOOK_SECRET held another environment's value and every webhook answered 401 for eight days with only a console log.

Root structural cause. scripts/preview-wrangler-config.mjs derives the preview config from production by deleting and overriding a hand-maintained list, so every new production var or binding reaches previews by default. Secrets are not checked against their environment at deploy time.

Candidates. A. Invert the derivation to an allowlist: every production key must be named in a keep, replace or drop decision, and an unknown key fails the script. B. A separate env.preview in wrangler.jsonc. C. Keep subtractive and add a post-deploy probe.

Screen. B is what the script's own comment rules out: a wrangler environment inherits from the top level, so it is the same leak in another file. C catches the leak after it has written production data. A passes.

Prototype. Census on origin/main: 10 production vars, 8 explicitly handled, 2 inherited silently (CONTACT_FORM_RECIPIENT_EMAIL, SENTRY_DSN); every binding kind handled. Cost of A today is two decisions.

Decision. Architecture, U7. A separate small unit probes webhook secrets at deploy by verifying a signed test payload (U15).

7. recorder-state (23)

Evidence. WIL-3449 (every "Finish your video" state added ad hoc), WIL-3359, WIL-3413 (Open page clickable while the link is preparing), WIL-3451 (recovery copy kept after the server has the video), WIL-3409 (blank recording saved after getUserMedia failed), 7d803d4cd, 3369d696b. RecordVideoRoute.tsx is 987 lines and took 16 fix commits.

Root structural cause. One boolean per concern in one route; no model of what a take is at any moment.

Candidates. A. A TakeState discriminated union with a reducer; the UI derives every button and message from the state, and switch is exhaustive. B. Keep booleans, add a lint on new useState<boolean> in the route. C. Move the state to the server.

Screen. B bans a symptom. C moves the same booleans. A is the 21 Sept audit's candidate 4 and passes.

Decision. Types, U11. No prototype needed: the fork is design, not empirical.

8. agent-process (23)

Evidence. Five Linear tickets WIL-3254 to WIL-3258 (PRs merged before verification, July). Corrections: "relied on verification before main changed" (session ccaf6629, 29 Sept), "added separate test suite" (9cddc5ce, 21 Sept), "shared artifact without public URL" (34f48772, 14 Sept), "tested only short videos" (52e6feda), "asked William to drive computer use" (ccaf6629, 30 Sept), "explained tradeoffs unclearly" (983347a1).

Root structural cause. Nothing fails when an agent skips a step that lives in a skill's prose. The merge rule, the public-URL rule and the root pnpm test rule are all text.

Candidates. A. A CI check that the PR carries a proof block naming its current head SHA, written by /ship; a stale SHA fails the merge. B. More text in the skills. C. A verification ledger outside the repo that the merge reads.

Screen. B is the level that failed. C already exists in the pstack store for autopilot runs but the repo cannot read it. A passes for the one repeat with five tickets; the rest are judgment calls and stay as skill text per the correct skill's level 4.

Decision. Tooling, U17. The remaining subclasses are listed as docs-level follow-ups, not units.

9. D1 boundary (27)

Evidence. Four commits reconcile fakes with query text (7dba602ab is one), 13 inline .first<{...}> row types and 2 hand-written *Row interfaces remain, 1074031dd (two copies of a body-size constant), WIL-3425 (malformed path encoding answers 500), WIL-3420 and WIL-3393 (jsdom timing flakes). The Blacksmith CI bot flagged "the checked-in row types match the migrations" on #942.

Root structural cause. Row shapes typed by hand at each read, and tests that fake D1 by matching SQL text so any query change breaks an unrelated test.

Prototype. Ad-hoc eslint selectors on origin/main (proto/eslint.proto.mjs): ROW-INLINE 13, ROW-HANDWRITTEN 2, FAKE-BY-TEXT 132 across 32 test files, mostly editor/tests/ where the router's tests live. createSqliteD1Database already exists and 8 test files use it.

Decision. Lint. Row types straight to error with a 15-item cleanup (U2). Query-text fakes as a per-file ratchet in eslint-suppressions.json whose message names the helper (U3). A package-boundary lint belongs here too, because packages/* are directories, not packages: 125 import statements reach into packages/*/src/<internal>, 55 need about 30 new index exports, and two packages have no index.ts (U1).

10. docs-drift (15)

Evidence. Four commits titled "reconcile feature map with source" (345e94513, 66a07c437, 705b9a4ea, 869154016), DEPLOY.md touched by 10 fixes, and the 24 Sept audit found ROADMAP, CONTEXT and SECURITY describing a deleted pipeline (purged in #818).

Root structural cause. Prose that mirrors code is a hand-synced list.

Candidates. A. Derive the feature map from e2e spec titles. B. Require every claim in a feature file to cite a path that exists, checked in CI. C. Delete the feature map.

Prototype. 40 feature headings against 16 e2e specs: not derivable one-to-one, so A fails today.

Decision. B as U9; C is a call for William (default below).

11. ci-gate-drift (9)

Evidence. WIL-3422 (310 type errors in 82 test files that were never typechecked), WIL-3421 (LOC ratchet existed only as prose, auth-session.ts grew unnoticed), WIL-3392 (staging e2e gate failed every run for six days), WIL-3498 (CI wait read a cancelled duplicate run), the memory note that a lane ran the editor filter instead of root pnpm test (#682) and that | tail -3 hid a red typecheck for an hour.

Root structural cause. The local gate and the CI gate are different commands, so an agent can run "the tests" and still be red in CI.

Decision. One just gate recipe that CI's check step calls verbatim and that the edit hook and skills name; check-ci-invariants.sh asserts ci.yml runs it (U8).

Decision. One lint left: refuse a DROP TABLE or rebuild of a table that has out-of-repo children in check-migrations-append-only.sh (U10).

WIL-3412, WIL-3485, WIL-3496, WIL-3500, WIL-3518 and two more. Route liveness and page deletion had separate owners. Fixed at the architecture level by the trigger in migration 0035 (#967). No unit.

Tier reasons, one line each.

  • U1 to U5, U9, U10, U16, U17, U18: lint, tooling or CI scripts; no Worker, binding, migration or auth path changes; blast radius is a red CI run.
  • U8: changes ci.yml and justfile only; a mistake blocks merges, nothing deploys differently.
  • U6: touches reads on the entitlement path for display; decisions still come from decideEntitlement; preview proof required.
  • U7: changes the preview deploy script only; production config is untouched; a wrong allowlist breaks previews, not production.
  • U11, U12: editor and router runtime behaviour on non-critical paths; U12 adds a 409 branch to page saves, preview proof with two tabs.
  • U15: adds a check to the deploy job; a false failure blocks a deploy, which is recoverable; no config change.
  • U13: a D1 migration and data deletion on the video path; a main push applies the migration before the router upload.
  • U14: rewires auth, rate limit and origin guards for every route.

Sequencing. Wave 1 (parallel, all Tier A, no dependencies): U1, U2, U3, U4, U5, U8, U9, U10, U16, U17. Wave 2: U6, U7, U11, U15 (Tier B), U18 after wave 1 lands. Wave 3: U12 after U5. Tier C units U13 and U14 are scheduled by William; U14 after U6 and U8.

Autopilot fit. Waves 1 and 2 suit autopilot-full with one owner per PR. U12, U13 and U14 suit autopilot-stack if William prefers to land them himself.

Out of scope, deliberately

  • copy-ux product fixes, the styling migration policy (styling audit, 2026-09-15), perf (preload and cache windows are measured in the 2 Oct audit), email delivery (Resend replacement decided 1 Oct), observability (canary shipped in #979), analytics accuracy, legacy data recovery (WIL-3355, WIL-3434), secret handling (two items, both fixed).
  • Making packages/* real pnpm workspace packages. The Fable critic in the 1 Oct audit asked for it; the boundary lint in U1 gives the same protection at a fraction of the change, and the laziness protocol says stop there until a second need appears.
  • Folding workspace-tree into the router. Still present at 1,144 lines on origin/main despite the 30 Sept plan; that is WIL-3165's call, not this plan's.
  • A prose rule table in AGENTS.md. William wants it tiny; U18 generates the table instead.
