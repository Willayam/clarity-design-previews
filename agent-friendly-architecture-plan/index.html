Agent-friendly architecture: plan

Clarity repo, plan phase only. Written 2026-10-04 against origin/main 346c85da7, revised after a cross-family critic pass (Codex gpt-6-astra, lanes/critic-astra.out). Nothing here has been pushed, ticketed or deployed. Store: ~/.claude/orchestrate/agent-friendly-arch/ (data tables, scripts, prototype results, decisions.tsv).

What this is for

Agents write most of Clarity's code now. Since 1 July 2026, 1,688 commits landed on main; 267 were fix-shaped, and the fix share rose from 16% of September's commits to 26% of October's. This plan names the mistake classes behind those fixes, with counts and evidence, and proposes repo changes that stop each class at the highest level that works: architecture first, then types, then a lint whose error names the fix, then a test, and prose last. Each change is a PR-sized unit with a verify command and a deploy-safety tier.

For William, the payoff is fewer follow-up fixes per feature and fewer corrections typed into agent sessions. For the next agent, it is a repo where the shortest path that compiles is the right one.

Limits on the data, so the numbers are read correctly.

  • Counts are observations, not unique incidents. The three sources are concatenated without deduplication, so one incident can appear as a commit and a ticket (0d9385b21 and WIL-3472 are the same webhook-secret outage). A class rank orders how often a shape was recorded.
  • "Follow-up fixes" are proximity, not causation. followup-fixes.tsv pairs a fix with the nearest earlier non-fix commit that touched the same file within four days. The 24 and 17 counts below are leads that were then read commit by commit, not measured causes.
  • The PR comments are shipping and verification reports by the agent account plus preview-bot links. There are zero inline review comments on these 300 PRs, so that source contributed no mistakes.
  • William's corrections are sparse because he is terse. The lanes kept 38 of 1,473 turns; a 22-row manual sample found no missed corrections, but recall on one-word redirects is unknown.

A class counts once it happened twice.

1. video-lifecycle (80)

Evidence. The feature commit with the most fixes within four days is 834286e75 "create a video node from an upload that is still in flight": 24, among them 0e9643e2d (fence the settle write), 092202728 (settle processing takes from the daily Mux list), f669df502 (two concurrent reads count one settle miss), 328355d78 (recorder blocked by backoff). Not all 24 are the same cause; the cluster also holds a webhook-secret report and a Sentry wrapper fix. Linear: WIL-3426, WIL-3441, WIL-3459, WIL-3453. workers/workspace-tree/src and its tests took 291 fix-file touches, the most of any directory.

Root structural cause. Video truth lived in three places (Mux, a JSON metadata bag, the browser), and readiness was settled from several readers with no single owner of state transitions. The lanes' causes read "settlement depended on someone reading the take", "selection and reducer writes were separate", "field lock inferred from presence of optional fields".

Candidates. A. One lifecycle module owns every transition of video state; others ask it. This is WIL-3494, and PRs 5 and 7 are merged (#936, #974, follow-up #992). B. Legal transitions as D1 CHECKs and triggers only. C. A reconciler cron that repairs what writers leave inconsistent.

Screen. B cannot express settle backoff or "ask Mux at read time" and leaves split ownership. C adds a second writer, the shape the 2 Oct audit told the repo to delete (the dual write). A passes and is mostly built.

Prototype. UPDATE, INSERT or DELETE on videos appears in two files on origin/main, video-row.ts and mux-video-ingest.ts. References to the JSON metadata fallback remain in video-row.ts, mux-clip-job.ts and video-edit-routes.ts. A location lint holds today with zero violations, but a location is not an owner: mux-video-ingest.ts still writes settlement fields directly, and 842137edd shows a write classifier that missed WITH ... REPLACE.

Decision. Finish the architecture (delete the dual write and JSON fallback, U13, Tier C) and fence it (U4), where the fence names the one module that may write and matches every write form, not three keywords.

2. styling-design-system (44)

Evidence. WIL-3386 (password toggle built twice on Input), WIL-3384 and WIL-3385 (stacking keyed on viewport width), WIL-3382 (no layering contract), 31 fix commits in editor components. eslint-suppressions.json holds 358 violations across 51 files and already fails when a file's count grows.

Decision. No new unit. The ratchet already blocks growth; a "must shrink on touch" rule would couple unrelated feature work to cleanup, and the styling audit of 2026-09-15 holds the open verdicts for this class.

3. auth-identity (37)

Evidence. eee141ecb (an ended grant still allowed access; entitlement had access_grants and users.expiration_date as competing sources), 147b1f6b2 (admin endpoints used different identity checks), f6d935248 (unlock token not bound to the password), WIL-3489 (Mux webhook missing from a hand-maintained origin-guard exemption list), WIL-3511 (each public POST wires its own rate limit), b27ecdf3e (Origin: null refused lead forms for 24 days), WIL-3505 (HEAD answers 404 where GET answers 302).

Root structural cause. Policy is wired per handler in an ordered if-chain (workers/frontend-router/src/index.ts, 869 lines), so every guard is a list someone must remember.

Candidates. A. A route table where each route declares its policy (auth, rate limit, origin guard, body cap) with required fields and one dispatcher that is the only export, so a route cannot exist without a policy; WIL-3401 scoped to policy as the 2 Oct audit recommended. B. Keep the if-chain and ban raw guard calls outside a wrapper. C. Middleware chain per route group.

Screen. B stops one shape, not the class, and keeps the exemption lists. C can work; it fails only if a handler can be mounted without the chain, which is the same requirement A has. A was chosen because it also removes method-matching drift (WIL-3505) and is the shape William already asked to review. Neither fixes entitlement tie-breaks (WIL-3507) or token binding; those are done.

Decision. U14, Tier C. The earlier idea of a lint confining expiration_date reads was dropped after reading the seven hits: account-profile.ts already calls decideEntitlement and the remaining fields are display and classification output, not competing decisions.

4. editor-save-state (35)

Evidence. 7dc906a7f "hold the stored draft revision and send it with every save" drew 17 fixes in two days: 33ca436da (create idempotent on an editor-minted id), 9659a417d (refuse a stale whole-document save), 6ddbf897c, 4c5d11730. Linear WIL-3515, WIL-3524, WIL-3411.

Root structural cause. Draft state was owned by React refs and the server accepted last-write-wins. Both are now fixed: the editor has one store, and journey-pages-native.ts:384-442 answers 409 with the current revision on a stale save.

Remaining gap. The shared store's saveDraft still accepts a call without expectedRevision; the HTTP handler supplies it, but a new internal caller (a generation job, a cron) can omit it and compile. Page writes from the client go through apiFetch and apiRequest wrappers in more than two files (HomeTreeRoute.tsx:764 DELETE, journey-page-duplicate.ts, journey-page-sharing.ts), so a transport-location lint would not establish ownership and is dropped.

Decision. Types: make expectedRevision required on the store's write signature and let the compiler find every caller (U12, Tier A). No lint unit.

5. copy-ux (32)

Product work, out of scope. The recorder items (WIL-3449, WIL-3359) share a cause with class 7; the state machine there prevents contradictory controls but does not choose copy.

6. deploy-config (24)

Evidence. Previews inherited production bindings or values five separate times: WIL-3176 (D1), WIL-3360 (R2 broker), WIL-3431 (84 analytics rows into prod), WIL-3488 (media key and signing secret), WIL-3517 (Mux Data). WIL-3472 and 0d9385b21: the production MUX_WEBHOOK_SECRET held another environment's value and every webhook answered 401 for eight days with only a console log.

Root structural cause. scripts/preview-wrangler-config.mjs derives the preview config from production by deleting and overriding a hand-maintained list, so every new production var, binding or secret reaches previews by default.

Candidates. A. Fail-closed derivation: every production var, every binding instance by name, and every secret name must appear in a keep, replace or drop decision; an unknown key fails the script. B. A separate env.preview in wrangler.jsonc. C. Post-deploy probe.

Screen. The script's comment rejects B because an env.preview entry would be deployable without the generator; it says nothing about inheritance, so B's real cost is a second config to keep in sync, a hand-synced list. C catches the leak after production data is written. A passes; the decision map stays hand-maintained but omissions become visible.

Prototype. 10 production vars, 8 explicitly handled, 2 inherited silently (CONTACT_FORM_RECIPIENT_EMAIL, SENTRY_DSN); service bindings other than R2_MEDIA pass through unchanged. The cost of A is those decisions plus one per secret name.

Decision. U7. A deploy-time webhook-secret probe was considered and cut: signing a test payload with the same configured secret proves nothing when that secret is the wrong one, and a live probe against production handlers has side effects. Noted as a follow-up needing a no-op design.

7. recorder-state (23)

Evidence. WIL-3449 (every "Finish your video" state added ad hoc), WIL-3359, WIL-3413 (Open page clickable while the link is preparing), WIL-3451 (recovery copy kept after the server has the video), WIL-3409 (blank recording saved after getUserMedia failed), 7d803d4cd, 3369d696b. RecordVideoRoute.tsx is 987 lines and took 16 fix commits.

Root structural cause. One boolean per concern in one route; no model of what a take is at any moment.

Candidates. A. A TakeState discriminated union with a reducer that owns only client recording and interaction state; every event carries the take id and a late async result for a take that is no longer current is dropped; UI derives buttons and messages with an exhaustive switch. B. Lint against new booleans. C. Move the state to the server.

Screen. B bans a symptom. C duplicates WIL-3494's server lifecycle in the wrong place. A passes.

Decision. Types, U11.

8. agent-process (23)

Evidence. WIL-3254 to WIL-3258 (five PRs merged before verification, July). Corrections: "relied on verification before main changed" (session ccaf6629, 29 Sept), "added separate test suite" (9cddc5ce), "shared artifact without public URL" (34f48772), "tested only short videos" (52e6feda), "asked William to drive computer use" (ccaf6629), "explained tradeoffs unclearly" (983347a1).

Root structural cause. Nothing fails when an agent skips a step that lives in a skill's prose.

Candidates. A. A CI check that the PR body's ## Proof block names the head SHA it verified; a different head fails, and editing the body re-runs the check. B. More skill text. C. Read the pstack verification ledger from CI.

Screen. B is the level that failed. C needs a store the repo cannot see. A catches the one mechanical shape (stale verification after a rebase or a merge of main) and nothing more; it cannot prove verification happened.

Decision. Tooling, U17, with that limit stated. The other subclasses are judgment calls and stay as skill text.

9. D1 boundary (27, of which about 10 are SQL-shaped)

Evidence. Four commits reconcile fakes with query text (7dba602ab is one); the Blacksmith bot flagged "the checked-in row types match the migrations" on #942. The rest of the grouped items are other boundaries: 1074031dd (two body-cap constants), 7a6ade175 (stored thumbnail leaked), WIL-3425 (path decoding answers 500), WIL-3420 and WIL-3393 (jsdom timing). They share "duplicated or untyped boundary" but not one fix.

Prototype. Ad-hoc selectors on origin/main (proto/eslint.proto.mjs): ROW-INLINE 13, ROW-HANDWRITTEN 2, FAKE-BY-TEXT 132 across 32 test files. Reading the hits: AccountSearchRow (admin-account-search.ts:28) is an API result, not a table row, and the gohighlevel-sync.ts hits are COUNT/SUM projections that no generated table type can describe. So the row-type rule needs a named-result escape, and the true cleanup is under 15. createSqliteD1Database exists and 8 test files use it.

Decision. Lint for the SQL subset only. U2 bans inline object types on .first<>/.all<> and hand-written *Row aliases that are plain object literals; a named type XResult = {...} for aggregates passes, and the message names packages/d1-row-types. U3 ratchets query-text fakes per file with a message naming the helper. A package-boundary lint belongs here as well because packages/* are directories, not packages: 125 import statements reach into packages/*/src/<internal>, 55 need exports that do not exist yet, two packages have no index.ts (U1). The index must be designed, not a barrel of everything currently imported; exporting 17 Mux names including credential types would widen the public surface rather than hide it.

10. docs-drift (15)

Evidence. Four commits titled "reconcile feature map with source" (345e94513, 66a07c437, 705b9a4ea, 869154016), DEPLOY.md touched by 10 fixes, and the purge of ROADMAP and SECURITY text describing a deleted pipeline (#818).

Candidates. A. Derive the feature map from e2e spec titles. B. Every cited path in a feature file must exist, checked in CI. C. Delete the feature map.

Prototype. 40 feature headings against 16 e2e specs: not derivable, so A fails today.

Decision. B as U9, with its limit stated: a path can exist after the behaviour behind it changed, so this catches dead references only. C is a call for William.

11. ci-gate-drift (9)

Evidence. WIL-3422 (310 type errors in 82 test files never typechecked), WIL-3421 (LOC ratchet existed only as prose), WIL-3392 (staging e2e gate red for six days), WIL-3498 (CI wait read a cancelled run), the memory notes that a lane ran the editor filter instead of root pnpm test (#682) and that | tail -3 hid a red typecheck.

The cancelled-run selection (WIL-3498) is a separate fix already noted on WIL-3524.

Units

Tier A merges on autopilot-full after an independent verify and a watched prod deploy; Tier B adds a staging or PR-preview runtime proof before merge and the rollback version captured from the deploy log; Tier C stops for William. Every verify includes a planted negative case: the check must fail on a deliberately wrong input before it counts.

Earlier drafts also held U5 (page-write location lint), U6 (entitlement read lint), U15 (webhook secret probe) and U16 (shrink-on-touch ratchet); each was cut for the reason given in its class.

Tier reasons.

  • U2, U3, U4, U9, U10, U17, U18: lint, tooling or CI scripts; no Worker, binding, migration or auth change; blast radius is a red CI run.
  • U8: changes ci.yml and justfile; a mistake blocks merges, nothing deploys differently.
  • U12: a type change; the compiler lists every caller and the diff is reviewable; no runtime behaviour changes for callers that already pass a revision.
  • U1: changes production import paths and package entry points, so Worker and editor bundles can change; preview smoke required.
  • U7: changes only the preview deploy script, but the incidents it addresses were previews writing production, so the proof is the generated config diff, not the deploy succeeding.
  • U11: recorder runtime behaviour; the recorder is a core path, so preview evidence covers failure and recovery, not only the happy path.
  • U13: deletes a data path on the video lifecycle and ships a migration; a main push applies migrations before the router upload and a Worker rollback does not restore deleted data.
  • U14: rewires auth, rate limit and origin guards for every route.

Sequencing. Wave 1, Tier A with no dependencies: U2, U3, U4, U8, U9, U10, U12, U17. They edit the shared eslint.config.mjs and eslint-suppressions.json, so each rebases on the previous merge; they are independent in content, not in files. Wave 2: U1, U7, U11 (Tier B). Wave 3: U18. Tier C: U13 after U4, U14 after U8, both scheduled by William.

Autopilot fit. Waves 1 and 2 suit autopilot-full with one owner per PR. U13 and U14 suit autopilot-stack if William prefers to land them himself.

Measuring the payoff

Rerun scripts/mine-git.sh 2026-10-04 in a month and compare, on a pinned window, three numbers: fix-shaped share of commits (26% in October so far), distinct fix commits within four days of a feature commit on the same file (184 since July), and corrections per session from mine-transcripts.py (38 in 47 sessions). Dedupe a commit and a ticket that cite each other before counting.
