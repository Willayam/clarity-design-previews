Each task is scored from the account's state afterwards, not from what the agent said. Publish, share and delete are approved by the harness acting as the account owner. Accounts are test accounts on PR previews.

What changed between the runs

Before. Main's connector: nine operations, reads plus page draft edits.

Round 1. 34 operations from one registry, shared by the MCP connector and the new clarity CLI. Typed schemas every host can read, refusals that say what failed and how to fix it, uploads, folders, video edits, page creation and AI drafts, settings, contacts, and publish, share and delete through the owner's approval.

Round 2. Fixes from round 1's failed cells and agent feedback: one approval for several video edits, folder deletes that say which pages move, replays that notice a deleted record, allowed values in refusals, an edit help operation, changed blocks in every edit answer, and a CLI whose help works everywhere.

Round 3. Agents hand the owner the approval link and end their turn instead of waiting, documents leave out empty fields (a page fell from 2,706 to 1,201 bytes), uploads say what to do next for their state, and a pending trim is reported as pending.

How to read the numbers

Seats are fresh agents: Claude (fable, opus, sonnet) and Codex (gpt-6-sol, gpt-6-astra) through the MCP connector, and two seats that had only a shell and the CLI. A failed call is a tool call the server refused. Round 2's seconds rose because agents waited up to 45 seconds for the owner in one call; round 3 tells them to hand over the link instead, and seconds fell.

The two failures in the last run: an agent with a shell found folders named Archive on the computer and asked which one to delete, and one Codex CLI agent added a new upload to an existing page instead of making a new page.

Parity on one base. The before run used a 95-row list of agent-eligible UI actions; later runs use the committed inventory of 124 rows, which adds admin, billing and client-only rows. On the same 95 rows, actions covered by a passing, state-checked task went from 39 to 85. 86 of the 95 have a task; the rest need a camera or browser-only state.

Grading. Results include reruns of cells that failed for infrastructure reasons (preview database blips, model capacity, a connector that started late) and check fixes found by reading failed cells. Check changes made after a run never lifted the before run: the tasks they touch already passed on every before seat.
