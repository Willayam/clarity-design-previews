AI chat: how it behaves with the real tools

30 October 2026. Two agents played the chat model over Clarity's live MCP tools on staging. Back to the design board.

What was run

An Opus agent ran six rep requests through the Clarity staging connector. A Codex agent (gpt-6.1-sol) ran seven more as the e2e test account through a wrapper that logged every call's time and size. Requests went from "make a follow-up page for Anna at Acme" through edits, a video swap, publishing and stats. The test account's publish was approved on the real approval page, and the live link came back through approvals_get.

What works

  • Edits land on the first try. Multi-change pages_edit calls succeeded using ids from the page outline.
  • Publishing stops for approval, and the approved result carries the share link.
  • The approval page already shows what the in-chat confirm card needs: the page, what goes live, password and expiry.

What has to change before it ships

  • Who the chat acts as. The kernel asks for approval only when the caller is an agent connection. A chat calling as the signed-in user would publish with no confirm. A chat calling as an agent would send the rep to an approve link for their own page. The chat needs its own caller kind whose publish and delete return a card the rep confirms in place.
  • Smaller answers. Library results carry playback and edit plumbing, page reads return the whole document, and edits return whole blocks with no before values. The chat needs compact library records and edit answers with before and after for the changed fields.
  • Facts before writing. With no pricing or booking link on hand, the first test wrote no prices and a Book a call button with no link. Agents made up an onboarding time and inferred a name from a URL. The system prompt must ask for missing facts before creating or changing a page, and the generator should get confirmed facts kept apart from instructions.
  • Weekly stats. "Who opened my pages this week" cannot be answered: stats are lifetime totals per page. It needs a stats tool with a date range.
  • Media in the outline. The outline does not say which blocks hold a video, so a swap needs the full document.
  • Waiting on generation. One run followed a fixed "check again in 30 s" hint and saw a 13 s job at 34 s. The chat should hold the call open and show progress.
